# RESUME 2026-09-27 (session 4: sound out, and the DSP56001 on the ARM)

Earlier state, rules and gotchas: `RESUME-20260926.md` (still valid).
Decisions of this session: `docs/DECISIONS.md` "Sound and DSP".

## Plan agreed with the user

- The DSP56001 is the last big piece.  The FPGA is at 92-94% ALMs, so the
  DSP runs **on the ARM** (Previous's interpreter in Main), the FPGA keeps
  the 68040's side of the host port.  "ARM now, FPGA later": a DSP core in
  the FPGA could later plug in behind the same host port.
- **No sound input** (no CODEC/microphone), **no DSP serial ports**
  (SSI/SCI): the MiSTer has no connector for them.
- Measured: Previous's DSP interpreter = **1.5 M instr/s on ARM core 0**
  (0.86 M on core 1, which Main keeps busy) = 12% of a 25 MHz 56001;
  compiler flags change nothing; gprof: the 56-bit maths (dsp_mul56,
  add56, ccr) dominate -> a later int64 rewrite could give 3-4x.
  Bench: `scratch/dspbench/` (bench.c + Previous sources + shims).

## The DSP link (commits d0fee87 here, 30c0815 in Main_MiSTer next-color)

- `rtl/tc_dsp.sv`: host port at $02008000 (ICR/CVR/ISR/IVR/TX/RX, HREQ,
  INIT, DMA byte pump incl. Turbo unpacked), SCR2 DSP bits, int_dsp ->
  status bit 14 (IPL4), link engine to the DDR3 mailbox at $30400000
  (FPGA word +0, ARM word +8, H2D ring +$1000, D2H ring +$2000, 256 x
  64-bit each; epochs {DSP resets, TX INITs, RX INITs}).  TX words go on
  the link at once in access order (bug found by the bench: an HF0 right
  after the last bootstrap word overtook it); TXDE = fewer than 2 unread
  words; RX queue 4.  Idle poll 1 ms, 4 us while SCR2 DSP_RESET = 1.
- tc_tdma DSP channel (dd_*, byte lanes, block end = IRQB, chaining).
- tc_machine: D_DSP, the mailbox port shared with the Ethernet bridge.
- Main: `support/next/next_dsp.cpp` (+ `dsp56k/`), thread on core 0 for
  core "NeXT-Color"; built md5 98d5a905 (scratch/MiSTer_98d5a905), NOT yet
  installed on .143 (it has 50aff88c).
- Benches: `bash scripts/sim_wsl.sh unit tc_dsp` (tc_dsp + Main's
  next_dsp.cpp + Previous's core through DPI; +arm_every=700
  +arm_slice=32 = the real ARM pace), tb_tc_scsi (DSP channel).  Sim POST
  NeXT> at 70,865,640 (the link's idle poll shares the DDR3 port);
  ddr3_model backs the DSP window.
- ARM speed work: 64-bit 56-bit helpers (scratch/dspbench/fast56.c proves
  them bit-exact on 20 M cases; patch_fast56.py) give only +5% on the A9
  (1.64 M/s): the time is spread over parallel moves, address generation
  (modulo) and dispatch (ARM gprof).  Not applied to Main yet.
- Test ladder on NeXTSTEP: /NextDeveloper/Demos/Mandelbrot.app (DSP
  drawing), Sound.app, `sndconvert` to mu-law then `sndplay`,
  `playscore`; the Sound Kit's DSP programs are /usr/lib/sound/*.snd
  (booter, mulawcodec, mono, hostdecompress...), the array processing
  library /usr/lib/dsp/*.dsp.  Link state on the MiSTer: `devmem
  0x30400004` (FPGA: $D5F1 + generation), `devmem 0x3040000C` ($D5A1 +
  generation it follows).

## DSP on hardware (11:00-13:30)

- Build d0fee87 seed 1 (+0.212 ns, 39,652 ALMs = 95%, md5 b2753af2) on
  .143 as `_Unstable/NeXT-Color.rbf`; fallback `NeXT-Color_85522cb_seed2.rbf`
  (sound only).  Main now c2e7cfad (next-color 6a3ae03; backups
  MiSTer.bak-20260927-50aff88c).  Local rbfs: d0fee87 seed 1, 85522cb,
  2cd616c (+ the failed-timing d0fee87 seed 2 copy, delete).
- The link comes up at core load (devmem: FPGA $D5F1/gen, ARM $D5A1/gen).
  The kernel's sound driver resets/starts the DSP at boot (12 messages).
- `sndplay` of a mono 22 kHz file runs the Sound Kit's mono.snd DSP
  program (192-word bootstrap, 4096-word DMA buffers, $050001 request, HF1
  handshake, host command $24 ends each buffer).  Two bugs found with
  `scratch/dspbench/ringmon` (live ring monitor on the MiSTer) and
  `proto.c` (replays a captured session through Main's DSP core on x86):
  1. RX depth 4 let the DSP run ahead of the real host port -> depth 1
     (Main 67f650c).
  2. **Previous r1851 DO-loop bug**: a JSR landing on LA+1 was taken as the
     loop end (dsp_postexecute_update_pc) -> the loop end is checked only
     after sequential execution (Main 6a3ae03).  Worth reporting upstream.
  Now mono plays in real time and **the user confirms it sounds right**;
  mu-law 8 kHz plays through the DSP in real time ("landline", as G.711
  should).
- Main's screenshot saved nothing after one reboot (no scaler header) and
  worked again after the next; `scratch/grab_fb.py` reads the scaler
  buffer directly (stride 3584, offset 192) for such cases.
- Tools: `scratch/ring_dump.py` (last 256 messages each way),
  `scratch/fb_click.py` (pointer steering with the framebuffer grab).
