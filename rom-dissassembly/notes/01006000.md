# Range $01006000 - $01007FFF: boot command, network boot, boot animation ISR, printf/console library

Listing lines 9625..12744. Reached from the reset-time C init and from the monitor
('b' command). Nothing in this range is a POST; the hardware touched is the interrupt
mask register (through `mg+$1A0`), the video frame interrupt source (three variants
selected by `mg+$3BE`), the level-3 exception vector, and the screen (through the
`vid_*` drawing helpers of range $01004000).

Conventions: `mg` = monitor globals pointer (`mg_get_ptr` = `sub_01000686` returns it
from `vbr+4`). Stack args are given as `$8(a6)`, `$C(a6)`, ... after `link a6`.

## Boot animation table at $0101A354 (data; labelled `sub_0101a354`)

38 entries of 10 bytes: `{word x, word y, long ptr, byte next, byte delay}`. `delay == 0`
entries are text (ptr -> string, drawn with `vid_printf_at`); others are icons (ptr ->
image struct, drawn with `vid_draw_image` at x, $340-y). `next` links the frames,
`delay` is the number of frame interrupts to wait. Sequences: 0 "Loading from disk"
(icons 1-3 loop), 4 "Please insert disk" (5-10), 11 "Please flip disk" (12-13), 14 "Bad

"Loading from network" (24-26), 27 "Bad network" (28), 29 "Loading from floppy" (30-32),
33 "Bad disk" (34-35), 36 "Please insert disk" (37..). Text at x=$226,y=$17C/$186;
icons around x=$280..$2A0, y=$1C0..$1E5 (upper left of the 1120x832 panel area).

## post_cache_tag_test  `sub_01006018`  (190 bytes)  called from $01001390 (POST)

Turbo only (NCC). Tag RAM size: `(NCC[$02210000] & $18) >> 3` -> `$10000 << n` bytes.
Region = `$03E00000 .. +size-$20`, stepping $20. For 16 rotations of pattern
`$D32B6D5B` (`lsl.l #1` each round): write pattern to every tag line, then read back
and compare only the low 2 bits (`andi.w #3`) with the pattern. On mismatch prints
"\nCache tag selftest failure.\n", "Memory error at location: 0x%x\n", "Expected: 0x%x
Received: 0x%x\n" through `printf_log` and returns the failing address in d0. On success
clears the whole tag RAM (`size/4` longs) and returns 0. Reads NCC control register
$02210000 (bits 4:3 = tag RAM size code).

## post_cache_clear  `sub_010060d6`  (54 bytes)  no caller found

Same size computation, then zeroes `size/4` longs of both tag RAM `$03E00000` and data
RAM `$03F00000`. Probably called through a pointer the descent did not resolve, or dead.

## boot_cmd  `sub_0100610c`  (1108 bytes, ends at $01006708)  called from $01001AD0

`boot_cmd(mg = $8(a6), how = $C(a6))`. Returns the kernel entry point in d0 (0 on
failure / when told not to launch). The caller ($01001AD0, the monitor/boot main) then
sets sr=$2700 and jumps into the kernel through `mon_call_on_stack`.

Locals: `params` at -$28(a6) (7 longs): `[0]` = `how` (arg 2, = mg+$140, 2 when issued
from the 'b' command) overwritten by 1 when an explicit "(ctrl..." spec is present;
`[1]` ctrl, `[2]` unit, `[3]` part, `[4]` = device entry `devops` pointer. `-$2C(a6)`:
2-char device name. `-$B8(a6)`: parse cursor. `-$BC(a6)`: mg+$16 = mg_nvram.

Parse (loop head `loc_01006132`, the whole thing restarts here when the command is
replaced):

1. `str_skip_space(mg+$F4)`. `?` -> usage. First two chars = device name; if the line is
   empty: NVRAM byte `mg_nvram+$12` (= RTC NVRAM offset $12, the boot command string
   `ni_bootcmd`) must be non-empty ("No default boot command.\n" otherwise); it is
   `strcpy`'d into mg+$F4, "Boot command: %s\n" printed, and the first entry of the
   device table whose name matches (`strncmp` 2 chars) is used ("Default boot device not
   found.\n"). Note: when the line is empty the device name is taken from the *matching
   table entry*, not from the NVRAM string.
2. Optional `(ctrl[,unit[,part]])`: numbers via `parse_number(..., base 10)`. With one
   number it is the partition (`params[3]`), two = unit,part, three = ctrl,unit,part.
   Any parse failure -> usage.
3. Device name looked up again in the table -> `mg+$F0` = name ptr, `params[4]` =
   entry+$8 (devops). `sprintf(mg+$100, "(%d,%d,%d)", ctrl, unit, part)`, `mg+$F8` =
   mg+$100, `mg+$FC` = mg+$100+strlen+1 where the rest of the line (up to a space or
   '-') is `strncpy`'d (max $40) as the file name; the flags ("-...") stay in the
   command string. Prints "boot %s%s%s\n" (name, spec, file).
4. Boot panel / interrupt setup (skipped when `mg+$3E5` bit 0 set or `mg+$170` bit 3
   set): `mg+$2FA = 0`; **exception vector $6C (level-3 autovector, at vbr+$6C) :=
   `boot_l3_isr_entry`**; then by `mg+$3BE`:
   * 0 (types 0,1,2, video DMA): mask reg `|= 1 << ((mg+$194==$139 ? $538 : $D30) >> 8 & $1F)`
     i.e. bit 5 INT_VIDEO (or bit 13); **DMA video limit register `$02004184 := $EA`**
     (Previous dma.c: limit $EA makes the video channel raise INT_VIDEO every frame).
   * 1 (type 3, NeXTstation Color non-Turbo): mask reg `|= $2000` (bit 13 = C16 video
     interrupt); **`$02118180.b := 7`** (colour video command register, mirror of
     $02018180: bit0 clear-int, bit1 enable-int, bit2 unblank).
   * 2 (all Turbo types, **Turbo Color**): mask reg `|= 1 << 13` (`$D30>>8 & $1F` = 13;
     bit 13 = INT_DISK / C16VIDEO, which is the TMC video interrupt); **TMC video
     interrupt register `$02200080.l := $06000000`** (byte 0 = $06: INT_MASK | ENABLE,
     Previous tmc.c: mask lets the frame interrupt through, enable turns video on).
   Then `mg+$4` bit 3 := copy of `mg+$170` bit 3.
5. If the panel is enabled: `vid_draw_image(x=$154, y=$134, image $01015F74)` (the boot
   panel background), `boot_anim_set(entry.$10)` ("Loading from ..."), and
   `boot_anim_step` twice.
6. Open loop (`loc_01006516`): `mg+$EC := mg+$E8` (reset allocations), `sr := $2700`,
   `d2 = ops.open(mg, params, 0, 0, 0)`. When `mg+$170` bit 3 is set any non-zero result
   returns 0 immediately (no retries in verbose/no-panel mode). Otherwise `sr := $2200`
   and switch on d2 through the jump table at `$01011D14` (5 longs):
   * 0 `$01006560`: OK, animation entry.$10.
   * 1 `$0100658C`: only meaningful when `devops == $0101B376` (optical): the boot command
     is replaced by "en" (`strcpy(mg+$F4, "en")`) and parsing restarts (no optical drive
     -> netboot). For other devices it is an error (falls into case 4).
   * 2 `$01006566`: animation entry.$13 ("Please flip disk"), remembers 3 as last state.
   * 3 `$0100657A`: animation entry.$12 ("Please insert disk").
   * 4 / >4 `$0100662A` (`boot_case_error`): animation entry.$11 ("Bad disk"/"Bad
     network"/"SCSI error"); for optical: `sub_0101027e(unit, 0)` (eject); then
     `delay_us(3000000)` and retry the open.
   Non-zero results other than a repeat of the previous one restart the animation; every
   non-zero result waits 3 s (`delay_us(3000000)`) and loops to the open.
7. Load: if `mg+$3E5` bit 0: clear `mg+$3AE` bit 28, `sr := $2200`. `d2 = ops.load(mg,
   params, &rest_of_line, 0, 0)` = kernel entry point. If 0 and the panel is enabled:
   if the file name is "diagnostics" -> error case (retry), else the NVRAM boot command
   is reloaded into mg+$F4 and the whole parse restarts.
8. Success (`loc_01006666`): `ops.close(mg, params)`; `mg+$F4 := skip_space(rest)`;
   `sub_0100a1a8` (keyboard/power poll); if d2 == 0 (only possible with `mg+$170` bit 3):
   video interrupt disabled: style 1 -> `$02118180.b := 5`, style 2 -> **`$02200080.l :=
   $05000000`** (INTERRUPT|ENABLE: clears the pending bit, drops the mask, keeps video
   on). NB: when d2 != 0 the frame interrupt is left enabled and the level-3 vector still
   points at boot_l3_isr; the caller's kernel launch masks interrupts.
9. Usage (`loc_010066BC`): "Usage: b [device[(ctrl,unit,part)] [filename] [flags]]\n",
   "boot devices:\n" and one "\t%s: %s.\n" line per table entry; returns 0.

The descent split this routine wrongly: `sub_01006300`, `sub_01006560`, `sub_01006566`,
`sub_0100657a`, `sub_0100658c`, `sub_0100660c`, `sub_01006612` are all inside
boot_cmd (jump-table cases or false pointers, see the end of this file). The bytes
`$01006700..$01006709` (`movem.l -$E0(a6),d2-d6/a2-a5; unlk; rts`) are the epilogue and
were dumped as data (`str_01006705`).

## boot_l3_isr  `$0100670A` (missed by the descent, 258 bytes to $0100680B)  called via jsr from boot_l3_isr_entry

The level-3 interrupt handler used while the boot panel is up. `link; movem d2/a2-a3`.
1. `if (ISR & $1000)` (INT_SCSI): if `mg+$302` non-zero call `(*mg+$302)(mg+$306)` (the
   SCSI driver installs `sub_0100dd4e` there); then `mg+$4 |= 4`.
2. By `mg+$3BE`:
   * 0: if `ISR & (1 << ((mg+$194==$139 ? $538 : $D30)>>8 & $1F))` (INT_VIDEO bit 5 on
     types 0-2): **video DMA CSR `$02000180.l := $00100000`** (DMA_RESET, releases the
     interrupt), `boot_anim_step()`.
   * 1: if `ISR & $2000`: **`$02118180.b := 5`** (clear int + unblank, int disabled),
     `boot_anim_step()`, **`$02118180.b := 6`** (enable int + unblank).
   * 2 (**Turbo**): if `ISR & (1<<13)`: **TMC `$02200080.l := $05000000`** (ack: writing
     INTERRUPT clears it, mask off), `boot_anim_step()`, **`$02200080.l := $06000000`**
     (mask on again). So on Turbo the frame interrupt is re-armed only after the
     animation step, i.e. at most one step per frame, and the interrupt is level-3 (IPL3)
     through bit 13 of `$02007000`.
   The code from `$010067C0` to `$0100680B` (the Turbo branch) was decoded as
   `sub_010067e0` starting in the middle of an instruction stream; the whole block
   `$01006700..$010067E0` needs to be re-decoded as code.

`boot_l3_isr_entry` `sub_010068be`: `movem.l d0-d1/a0-a1,-(sp); jsr $0100670A; movem;
rte`. `sub_010068ba` is a stray `link.w a6,#0` in front of it and `$010068CE` a stray
`unlk; rts` (compiler emitted a normal function frame around the asm handler).

## boot_anim_step  `sub_0100680c`  (174 bytes)  called from boot_l3_isr and boot_cmd; installed at mg+$30E

If `mg+$4` bit 3 (panel disabled) is clear, `mg+$2FA` (current entry) non-zero, and
`--mg+$2FE <= 0`: draw the entry: `delay != 0` -> `vid_draw_image(x, $340 - y, ptr)`
(icon), `delay == 0` -> `vid_printf_at(x, y, 1, ptr)` (text, clears the text area).
Then `mg+$2FE := delay`, `mg+$2FA := $0101A354 + 10*next`. Always: unless `mg+$3AE` bit
4, call `sub_0100a1a8` (keyboard / power-key poll: this is what lets the user interrupt
a boot with a key press). Returns `mg+$4 & 8`.

## boot_anim_set  `sub_010068d2`  (66 bytes)  arg: sequence index (byte, -1 = none)

`mg+$2FA := $0101A354 + 10*n`, `mg+$2FE := 0`, `mg+$30E := boot_anim_step`. With n == -1
nothing is changed.

## boot_load_image_header  `sub_01006914`  (182 bytes)  called from tftp_load_kernel $01006CB6 and the disk loader $0100EEB4

`(buf, long *len_in_buf, long *load_addr, long *entry)`. Two formats:
* a.out: `buf.w[2] == $0107` (OMAGIC): text+data size = `$4+$8`, entry = `$14`, header
  $20 bytes skipped (`*len -= $20`), load address = entry.
* Mach-O: `buf.l[0] == $FEEDFACE` and filetype `buf.l[3] == 5` (MH_PRELOAD). Walks the
  first two load commands (`d1 = 0..1`) at `buf+$1C`: for the first `LC_SEGMENT` (cmd 1)
  load address = entry = `vmaddr` (+$18), the buffer pointer is advanced by `fileoff`
  (+$20) and `*len` reduced accordingly; every LC_SEGMENT adds `filesize` (+$24) to the
  total. Only 2 commands are examined (fixed upper bound), a NeXT kernel preload image
  has __TEXT then __DATA.
Then `if (*len > 0) mem_move(buf, *load_addr, *len); *load_addr += *len`. Returns the
number of bytes still to load (total - copied), or 0 with "unknown binary format\n".

## Ethernet boot ops (`$0101A582`)

### enet_boot_open  `sub_010069cc`  ops[0](mg, params)
`state = mem_alloc($73C)`, stored at `params->$20`; broadcast MAC (`dat_0101a57c` =
FF FF FF FF FF FF) copied to `state+$22` (server MAC); `devops.init(params)` (`enet_init`)
-> if 0 returns 4 ("Bad network" retry loop); else copies the 6-byte result (our MAC,
returned as a pointer) to `state+$1C` and returns 0.

### enet_boot_close  `sub_01006a2e`  ops[1](mg, params): `devops[1]()` (`sub_010095b2`).

### tftp_load_kernel  `sub_01006a44`  (974 bytes)  ops[2](mg, params, &rest)
State layout (`state = params->$20`): `+0` last-send time, `+4` retry backoff mask
(init $7FF), `+8` timeout counter, `+$C` retransmit counter, `+$10` "got first data",
`+$14` random wait, `+$18` our IP, `+$1C` our MAC, `+$22` server MAC, `+$28` expected
block number, `+$30` load pointer, `+$34` BOOTP tx packet, `+$18A` receive buffer
(ethernet frame), `+$2E0` TFTP tx packet (ethernet header + IP at +$E + UDP at +$22 +
payload at +$2A), `+$50E` second receive buffer. `+$18A+$3E` = server IP from the reply.

1. `bootp_request(mg, params, &rest)`; returns 0 on failure.
2. Builds the RRQ: IP v4/ihl 5, TTL $FF, proto $11 (UDP), src IP `state+$18`, dst IP
   `rxbuf+$3E` (siaddr of the BOOTP reply); prints "Booting %s from %s\n" (file,
   server name `rxbuf+$56`); src port = `(timer_read_ms() & $3FF) + $400`, dst port 69;
   opcode 1; file name copied from `rxbuf+$96` (the BOOTP `file` field), mode "octet";
   UDP length, IP length set; ARP/no ARP: the server MAC is whatever answered BOOTP.
3. Main loop (up to 49 timeouts, `state+$8`): resend when `timer_read_ms() - last >=
   wait` through `net_send_ip(mg, params, state, 0, 0)`; after every send the backoff
   mask doubles (`$7FF -> $FFF ...`) and `wait = timer_read_us() & mask`; after 80
   retransmits of the same block it gives up on ACK-resend. `net_poll_recv(mg, params,
   state, 0)` returns a frame: must be UDP, dst port ours, and (after the first data)
   from the recorded src port `+$1E`. Opcode 5 (ERROR): prints "\ntftp: %s\n" and fails.
   Opcode 3 (DATA): block number check (wrong block -> resend the last ACK up to 1000
   times); for block 1 the header is parsed with `boot_load_image_header` (data at
   `rxbuf+$2E`, data length `d3 = UDP length - 12` (UDP header 8 + TFTP header 4)), later blocks are copied
   with `mem_move` to `state+$30` (skipping negative "remaining header" bytes); an ACK
   (opcode 4, block n) is sent through `net_send_ip(..., which=0)` with a 12-byte UDP
   payload; a data block shorter than 512 (`d3 <= $1FF`) or all bytes loaded ends the
   transfer.
4. On completion: builds the boot argument string `sprintf(-$88(a6), "%s(%d,%d,%d)%s",
   mg+$F0, ctrl, unit, part, mg+$FC)` (or "%s()%s" when `params[0] != 1`), prints a
   newline, and **calls the loaded image directly**: `jsr (a0)` with a0 = `-$8(a6)` =
   the entry point from the header parser, argument = pointer to that string; the
   result of that call is what tftp_load_kernel returns (the network boot image is a
   second-stage loader that returns to the ROM with the kernel entry, or 0 on failure). "tftp: timeout\n" after 49 timeouts.

### bootp_request  `sub_01006e12`  (986 bytes)  (mg, params, char **file)
Builds the BOOTP request in `state+$34`: IP v4/5, `id` incremented, TTL $FF, UDP, src IP
0, dst IP $FFFFFFFF, ports 68 -> 67, payload cleared ($12C bytes), op 1, htype 1, hlen 6,
xid = `timer_read_us() ^ (secs?)`, chaddr = `state+$1C`; if the boot file is
"server:file" (`str_index(file, ':')`) the server name goes into `sname` (`+$56`) and
"from %s" is printed after "Requesting BOOTP information"; the file name (up to space or
'-') goes into `file` (`+$96`); vendor area (`+$116`) = "NeXT", `vend[4] = 1`,
`vend[6] = 0`; UDP length $134. Send/receive loop (5 tries per round, random backoff
`timer_read_us() & mask`, mask doubling from $7FF): `net_send_ip(mg, params, state, 1,
retry)` (which = 1 -> the `+$34` packet, broadcast), `net_poll_recv(..., 1)`; a reply is
accepted when length > $155, UDP, dst port 68 (`+$24 == $44`), xid matches, op 2 and
`chaddr` equals ours (`mem_cmp`). If `reply.vend[6] == 0`: prints " [OK]\n", server MAC
:= reply ethernet source (`rxbuf+$6` -> `state+$22`), our IP := `yiaddr` (`rxbuf+$3A` ->
`state+$18`), returns 1. Otherwise (NeXT login extension): `vend[6]` 1 or 2 -> after
`delay_us(50000)`, `mg+$3AE |= $10000000`, `con_gets(vend+8, $38, echo = (vend[6]==1))`,
`mg+$3AE &= ~$10000000`, copies `vend[6..7]` back into the request and resends (this is
the "user name / password" prompt of NeXT network boot; `vend+8` of the reply is printed
first as the prompt after `sub_0100ab1e` reformats it); `vend[6] == 3` -> dst IP :=
-1 and `vend[6..7] := 0` (restart); other values restart the round. " [timeout]\n" and 0
after 5 unanswered rounds. `sub_0100aba4` is called before both result messages.

### net_send_ip  `sub_010072a8`  (mg, params, state, which, arg)
`which` 0 -> packet `state+$2E0`, 1 -> `state+$34`, else returns -1. Ethernet type
$800, dst MAC `state+$22`, src `state+$1C`; IP checksum = `~net_ip_checksum(iphdr, 20)`;
length = `IP length + $E`, min 60; `devops.write(pkt, len, arg)` (`enet_write`).

### net_poll_recv  `sub_01007354`  (mg, params, state, which)
`which` 0 -> buffer `state+$50E` (max $22E), 1 -> `state+$18A` (max $156). `len =
devops.read(buf, max)` (`enet_read`); 0 -> 0. If our IP is known (`state+$18`) and the
frame is not broadcast (`mem_cmp(dst, FF..FF, 6)`): ARP (type $806) -> `net_arp_reply`
and 0; IP (type $800, len > $21) whose IP destination (`iphdr+$10`) == ours -> return len. Broadcast frames (or before we
have an IP): return len if IP, len > $21 and the ethernet destination equals our MAC
(`buf` vs `state+$1C`) -- so BOOTP replies must be unicast to our MAC.

### net_arp_reply  `sub_010071ec`  (mg, params, state, frame)
For htype 1, op 1, ptype $800, target IP == ours: reply built in place (target := sender,
sender := our MAC/IP, op 2, ethernet dst := sender MAC, src := ours) and
`devops.write(frame, 60, 0)`.

### net_ip_checksum  `sub_0100743c`  (buf, len): sum of 16-bit words with end-around carry, low 16 bits returned (caller inverts).

## Console and printf

* `con_putc_crlf` `sub_01007480` (c): LF is preceded by CR; `con_putc` (`mg_putc`).
* `print_char_sink` `sub_0100766e` (c, dest): dest 1 -> `vid_draw_char`; dest 2 -> if
  `mg+$170` bit 3 clear append to the log buffer at `*(mg+$320)++` else console; dest 0
  -> console; any other value is a `char *` and the char is stored (`sprintf`). Returns
  the (advanced) dest.
* `print_number` `sub_010076d2` (value, base, zero_pad, width, signed, dest): base 10
  with negative value prints '-'; digits from "0123456789abcdef" ($01013EA2), padded
  with '0' or ' ' to width.
* `vprintf` `sub_01007876` (fmt, dest, argp): the format switch is the jump table at
  `$01011D28` (84 longs, index = char - '%', range '%'..'x'): `%` $01007B24, `0`
  $010078D6, `1`-`9` $010078DA (width), `D`/`d`/`u` $010078E4, `O`/`o` $010078E8,
  `X`/`x` $010078E0, `b` $01007926, `c` $01007904, `l` $010078BC (ignored), `s`
  $01007B06, everything else $010078AE (dropped). `%c` prints the non-zero 7-bit bytes of
  a long from the top (so `%c` with 'ABCD' prints "ABCD"). `%b` ($01007928..$01007B05,
  dumped as `str_01007928/str_010079c0/str_01007a34/str_01007afc` -- all code) is the
  BSD kernel `%b`: value, then a description string whose first byte is the base; bytes
  < $20 are bit numbers followed by a name, printed as `<NAME,NAME>`; bytes with top
  bits $E0/$C0/$80 describe multi-bit fields (`$E0`: field value match -> name, `$C0`:
  `NAME=value`, `$80`/`$00`: named bit). Used by the register dump commands. Output
  goes to `print_char_sink`; the string sink is NUL-terminated at the end (only when dest
  > $100 so console/screen/log are not).
* `printf` `sub_01007772` = vprintf to console. `sprintf` `sub_0100778a` (buf, fmt, ...).
  `printf_log` `sub_0100785c` = dest 2 (the POST error messages: they go to the log
  buffer unless verbose). `print_line` `sub_01007b38` (s): printf(s) + "\n".
* `vid_printf_at` `sub_010077a4` (x, y, clear, fmt, ...): only when `mg+$170` bit 3 is
  clear. `vid_draw_image_onscreen(0, $A, image $01015580)` (redraws the panel header?),
  then when `clear` != 0 fills rows $154..$1B8, pixel columns $226..$280 (`(x*bpp)/…`
  computed from `mg+$324/$328/$368`) with the background long `mg+$340`; cursor
  `mg+$1CE := x<<16 | x`, `mg+$1D2 := y`; `vprintf(fmt, 1, args)`.
* `vid_draw_char` `sub_010074b2` (c): LF -> `y += 20`, `x := line start`. Otherwise
  glyph metrics at `$0101A4D0 + 6*c` = `{x_in_font, row_offset, width, rows, y_adjust,
  0}` (so the table really starts at $0101A4D0 and overlaps the boot device table for
  the control characters -- only $20..$7F are ever printed); source pixels come from the
  font image at `mg+$374` (row `$3C - rows - row_offset`), destination at
  `mg+$368 + (y + $3C - rows... ) * bpl`; per `mg+$324`: 16 bpp -> `bf_extract`/
  `bf_insert` per pixel (colour), 4 bpp -> bytes, 2 bpp -> words, 1 bpp -> longs
  (width counts units of that size). Advances `x += width + 2`, `sub_0100b2b2` /
  `sub_0100b2f4` before/after (cursor hide/show?).

## Monitor input helpers

* `con_gets` `sub_01007b5c` (buf, size, echo): reads with `con_getc`; $08/$7F backspace
  (echoes "\b \b" = `dat_01013eb3`), $15 kill line, $17 erase word (back over spaces then
  to the previous space or '/'), CR/LF terminate (echo LF), $FF returns -1 (console
  lost?), buffer full rings BEL ($07). Returns length + 1.
* `str_skip_space` `sub_01007ca8`.
* `parse_number` `sub_01007cd8` (str, long *out, base): leading '-' negates, '~'
  complements, "0t" forces decimal, "0x" hex, base 0 = `mg+$192`; digits via
  `str_index("0123456789abcdef", c)`; '.'-separated groups are packed a byte at a time
  (`acc = acc << 8 + group`) so "192.42.172.1" gives an IP address and "0,1,2" style
  arguments work. Returns pointer past the number (spaces skipped) or 0 when no digit.

## Memory helpers

* `mem_alloc` `sub_01007dd6` (n): `mg+$EC -= n`, `mem_zero`, returns the new brk. This
  is the `mg_alloc` slot mg+$2EA (used by the disk drivers through mg+$2EA at $0100F0C8).
  Its epilogue `$01007E06..$01007E0B` (`unlk; rts; nop`) was dumped as `str_01007e06`.
* `abs_l` `$01007E0C` (unreferenced 10-byte `abs()`).
* `mem_cmp` `sub_01007e16` (a, b, n): 0 equal / 1 different.
* `mem_move` `sub_01007ec8` (src, dst, n): forward or backward byte copy. The long-copy
  fast paths at `$01007EEE..$01007F65` and `$01007F7C..$01007FF1` are unreachable (the
  `bra.l` before them was patched to skip them) -- correctly left as data, but they are
  code bytes.
* `mem_zero` `sub_01007ffc` (p, n).

## Monitor command dispatch (outside this range, mapped as requested)

The monitor loop (`$01001EDC`, range $01000000) takes the first character of the line,
subtracts '?' (`addi.b #$C1`) and indexes the 53-entry table at `$01011C40` (chars '?'..
's'); default `$010022BA` (unknown command). The help text is `str_01014cd8`
("NeXT ROM monitor commands: ...", printed by `$01002C3C`).

| char | handler | command |
|---|---|---|
| `?` / `h` | $010022B0 | help |
| `P` | $01001EF8 | "New password: " (set NVRAM password) |
| `R` | $01002278 | R [radix] set input radix (mg+$192) |
| `S` | $0100223A | S [fcode] open function code |
| `a` | $01001FFE | a [n] open address register (table $0101467C) |
| `b` | $01001FD8 | boot: mg+$F4 := rest of line, mg+$140 := 2, re-enter through `mon_call_on_stack` -> `boot_cmd` at $01001AD0 |
| `c` | $010022CC | continue at last pc |
| `d` | $01002012 | d [n] open data register (table $010145C8) |
| `e` | $0100219A | e [lwb] [alist] [format] examine, plus ec / ej / eo / ef |
| `m` | $0100203A | print memory configuration (uses mg+$3BA, strings at $010149C4..) |
| `p` | $0100213A | inspect/modify configuration parameters (NVRAM) |
| `r` | $01002026 | r [regname] processor register (table $01014730) |
| `s` | $01002168 | s [systemreg] system register |

The tables at `$010145C8` / `$0101467C` are the d/a register descriptor tables (name
pointer $01012C00.., register number, ...) and `$010149C4..$01014A84` is the SIMM
description string table used by 'm'; none of them is a command table.

## Machine-type applicability

* Turbo Color (types 5,7,9,$B) and all other Turbo types: `mg+$3BE == 2` -> TMC video
  interrupt register `$02200080` ($06000000 arm / $05000000 ack) and interrupt bit 13.
* Type 3 (non-Turbo colour): `$02118180` byte writes 7 / 5 / 6.
* Types 0,1,2: video DMA channel (`$02000180` CSR, `$02004184` limit) and bit 5.
* NCC cache tests: Turbo only; mg+$3CA/$3CE (NCC pointers) are set only for types
  6,7,$A,$B (`sub_01000d86`/`sub_01000dac`), the NCC-equipped Turbo variants.

## Hardware writes in this range (order as executed)

| where | register | value | meaning |
|---|---|---|---|
| boot_cmd $01006464 | int mask (`*mg+$1A0`) | `\|= 1<<5` or `1<<13` | enable video frame interrupt (style 0) |
| boot_cmd $01006468 | `$02004184` (video DMA limit) | `$000000EA` | style 0 only |
| boot_cmd $0100647C | int mask | `\|= $2000` | style 1 |
| boot_cmd $01006484 | `$02118180.b` | `$07` | style 1: clear int, enable int, unblank |
| boot_cmd $010064B6 | int mask | `\|= 1<<13` | style 2 (**Turbo**) |
| boot_cmd $010064BE | `$02200080.l` | `$06000000` | **Turbo**: TMC video INT_MASK + ENABLE |
| boot_l3_isr $0100678E | `$02000180.l` | `$00100000` | style 0: DMA_RESET video channel (ack) |
| boot_l3_isr $010067B0/$010067BA | `$02118180.b` | `$05` then `$06` | style 1 ack / re-enable |
| boot_l3_isr $010067F0/$010067FC | `$02200080.l` | `$05000000` then `$06000000` | **Turbo** ack / re-enable |
| boot_cmd $010066A6 | `$02118180.b` | `$05` | style 1 disable after load (d2==0 path) |
| boot_cmd $010066B2 | `$02200080.l` | `$05000000` | **Turbo** disable after load (d2==0 path) |
| post_cache_tag_test | `$03E00000..` | pattern / 0 | NCC tag RAM |
| post_cache_clear | `$03E00000..`, `$03F00000..` | 0 | NCC tag + data RAM |

For the FPGA core: the boot animation needs a periodic level-3 interrupt with bit 13 of
the interrupt status register set once per frame while `$02200080` byte 0 has bit 1 set,
cleared by writing bit 0; the ROM writes the register as a 32-bit long with the value in
the top byte.

## Descent problems to fix in the generator

* `$01006700..$010067E0`: code, not data. `boot_cmd` epilogue at $01006700; a function
  (`boot_l3_isr`) starts at `$0100670A` (reached only by `jsr dat_0100670a.l` at
  $010068C2, which the descent did not follow). `sub_010067e0` is not a routine start.
* `$01007928..$01007B05`: code (vprintf `%b` case, entered from the jump table at
  $01011D28 entry 'b' = $01007926); dumped as strings `str_01007928`, `str_010079c0`,
  `str_01007a34`, `str_01007afc`.
* `$01007E06..$01007E15`: `unlk; rts; nop` epilogue of mem_alloc plus `abs_l` at
  $01007E0C; dumped as `str_01007e06`.
* Jump tables: `$01011D14` (5 entries, boot_cmd result switch at $01006554) and
  `$01011D28` (84 entries, vprintf switch at $010078CA) are data tables, not code; the
  listing shows them as instructions.
* False routine starts from immediates that look like pointers: `sub_01006300` (from
  `$01007894`, inside `cmpa.l #$100,a1`), `sub_0100660c` (`$0100A0EC`, `$0100A728`),
  `sub_01006612` (`$0100A67E`), `sub_010067e0` (`$0100A224`). `sub_010068ba` and the
  case labels `sub_01006560/6566/657a/658c` are inside other routines.
* `$0101A354..$0101A4D0` (animation table), `$0101A4D0..$0101A7D0` (font metrics),
  `$0101A502..$0101A56A` (boot device table), `$0101A582`, `$0101B1CC` (ops tables) are
  data.
* `mem_move` fast paths `$01007EEE..$01007F65`, `$01007F7C..$01007FF1` are dead code
  (fine as data, but they are instructions).

## Uncertain

* `mg+$374` as "font image base": inferred from `vid_draw_char` reading glyph rows
  relative to it and `vid_draw_image_onscreen` swapping it into `mg+$368`; it may instead
  be the visible framebuffer with the font pre-rendered off-screen in rows 0..59 (the
  value $04100000 for Turbo is RAM bank 0, not VRAM). Check range $0100B000 notes.
* `sub_0100a1a8` is described as keyboard/power poll from its strings only.
* The exact semantics of the TFTP length arithmetic (`udplen - 12` vs `- $F4`) were not
  traced instruction by instruction; block handling is otherwise standard RFC 1350.
* `mg+$3E5` bit 0 meaning (headless / "no panel") is a guess from its use.
