# Range $0100001E .. $01001FFF (Rev 3.3 v74)

Listing lines 8..2846. Reset path, pre-stack helpers, BMAP DRAM sizing (non-Turbo),
`mg_init_machine` (sub_01000c9c), `mon_init` (sub_01000ec6), `fd_pick_default_boot`
(sub_0100187c), `exc_dispatch` (sub_010018d4) and the first monitor commands.
Names in `names/01000000.py`.

Conventions: "mg" = monitor globals pointer; "nvram" = the 32-byte copy at mg+$16;
"POT" = nvram byte 14 (`ni_pot[0]`, bits from Previous `rtcnvram.c`: 1 POT_ON, 2 EXTENDED,
4 LOOP, 8 VERBOSE, $10 TEST_DRAM, $20 BOOT, $40 TEST_MONITOR). Machine type = SCR1 bits 15:12
(Turbo Color = 5). Everything marked **TC** is on the Turbo Color path.

---------------------------------------------------------------------------------------------

## 1. Boot sequence for machine type 5 (Turbo Color), from reset to leaving this range

Registers d2/isp/msp are the only "variables" until step 10 (no stack). Continuations are
passed in a0/a5/a6/a7 and entered with `jmp (aN)`.

## 2. Routine notes

### reset_entry / sub_01000042 / sub_01000062 / sub_01000092 / sub_010000b0
See steps 1-3. Non-Turbo details: sub_01000042: cacr = $8000, BMAP+4 = $C7000000, a5 = sub_01000062, jmp loc_01000992 (mem_bmap_size_dram). sub_01000062: BMAP+$C = $80000000, BMAP+$38 = $E1000000, BMAP+0 = SCR1 & $F0000000 (slot id), SCR2 \|= $800.
Type 0 (loc_0100017e): cacr = $19, SCR2 \|= $1000 then \|= $800; index = (isp&3)<<2 \| (isp&$30)>>4 \| type<<5, +16, x5 into dat_01014af8 (5 bytes each) copied to $02106010..$02106014 (AT&T 7213 mirrored bytes, Previous does not model them), `$02004188 = 0` (Ethernet RX DMA CSR). Types 1,2 (loc_010001f2): if SCR1 bits 11:8 (cpu rev) < 1: BMAP+$34 = BMAP+$30 = $40000000; then the same enet table copy. Type 3 (loc_0100027a): BMAP+$C = $C0000000, `$02118190 = $0A`, `$02118180 = 0` (SCC clock/serial interface regs), SCR2 \|= $80.
dat_01014af8 rows (idx: bytes): most are `00 00 48 00 00`; idx 4/20 `19 28 08 10 00`, 5/21 `31 38 68 0D 00`, 8/24 `1A 28 00 10 00`, 9/25 `3E 78 00 0C 00`. Non-Turbo only.

### tmc_reset_config sub_010002b4 (TC)
Inputs: isp = SCR1 (cpu speed = bits 2:0, mem speed = bits 5:4), msp = type. Writes in order:
1. cacr = $8000.
2. **$02200010 (TMC control)** = $04008380 \| (cpu==7 ? $08000000\|$01F40000\|3 \| (mem==1 ? 8 : $C) : ($01770000 \| (mem==3 ? $08000000 : 0))). So a 33 MHz Turbo (cpu field 7, Previous default) writes **$0DF4838F** (mem field 0,2,3) or **$0DF4838B** (mem field 1); slower CPUs write $05778380 / $0D778380. (Previous' reset value is $0D17038F; bits 8-10 of the byte 2 = local-only/ROM-local/parity are 1,1,0 here, i.e. byte 2 = $83.)
3. **$02208008 = 0** (ADB INTMASK), **$02208018 = 0** (ADB CONFIG).
4. Colour types (5,7,9,B): if !(SCR2 & $1000): **$02200088 = $165A10D0** (fporch 11, sync 11, bporch 33, display 208 in the TMC field layout fporch[31:25] sync[24:19] bporch[18:12] display[11:0]) and **$0220008C = $10412270** (fporch 8, sync 8, bporch 18, display 624). Mono types: $6302F118 (49/32/47/280) and $00438340 (0/8/56/832), then TMC control bits 1:0 := 2 (`(ctrl & ~3) | 2`). The colour "display 208 / 624" values do not decode to 1120x832 with the mono unit; the units for the colour timing are unknown (flag).
5. loc_010003cc: **$02007800 = 0**.

### reset_pick_stack .. reset_mg_in_dram (sub_0100041e, loc_010004c2, sub_010004d0, loc_01000508, sub_01000514)
See steps 8-10. The mono continuation sub_010004d0 is identical to sub_01000514 except mg = VRAM+$3F800 and no sub_01003a9c call. Both store mg_sid = SCR1 >> 28 (arithmetic shift, so slot id $F -> -1) and mg_machine_type = msp.

### exc_common_entry loc_010005ae and the frame layout seen by exc_dispatch
With `link a6` in exc_dispatch, a6+8 = frame base: +$8 d0 .. +$44 saved a7 (the exception frame address), +$48 usp, +$54 sfc, +$58 dfc, +$5C vbr, +$64 cacr, +$8C SR, +$8E PC, +$92 format/vector word, +$94.. the words above the frame (for $700: mg, d2, return trap; for format 7: +$A0 = fault address). Vector offset = `bfextu $92(a6){4:12}`, format = `bfextu $92(a6){0:4}`.

### Small helpers
* sub_0100067a mg_set_ptr / sub_01000686 mg_get_ptr: the mg pointer lives at **vbr+4** (vector 1, unused in RAM). sub_01000690 get vbr, sub_01000696 set vbr, sub_010006a0 IPL.
* sub_010006ac mon_call_on_stack(sp, fn, a1..a13): a7 = sp, pushes args $44..$C downward, `jsr (a1)`; never returns to its caller.
* sub_010006f4/sub_010006fa mon_return_trap: the return address handed to booted programs; builds a vector-$600 frame with SR $2700 and enters exc_common_entry (reported as "Exception #384 (0x600)").
* sub_0100070e..sub_0100079a: `moves` read/write long/word/byte with the function code given as the 3rd argument (sub_01000728 uses a plain move.w, probably a bug in the original). sub_010007c6 / sub_010007e2 bit-field helpers.
* sub_010008e2 mon_enter_from_os (mg+$3AA callback): saves all regs, BMAP+4, a7, tc, cacr, itt0/1, dtt0/1 at vbr+$100..$118, goes transparent via loc_01000c68 -> sub_01000930 (cacr $8000, re-runs BMAP sizing) -> sub_01000946 restores everything and `rts` to the OS. On Turbo the BMAP write at $010008e6 would bus-error; this callback is non-Turbo oriented.
* loc_01000992..sub_01000c04 mem_bmap_size_dram (NON-TURBO only, entered from sub_01000042 and sub_01000930): programs BMAP +$4 (\|= $40000000), +$1C (mode words $70000000, $50000000, $20000000, $80000000, $A0000000, $30000000, $90000000, $B0000000), +$18 (bank address), +$20 (move16 of dat_01000c38/dat_01000c58 patterns) and reads back +$10/+$14; loc_010007f4 finds the address bit where the read-back matches. Data at $01000c28..$01000c67 are the move16 source patterns ($FF x 16 then zeros). Not needed for the FPGA (Turbo has no BMAP).
* loc_01000c68 mmu_transparent_setup: see step 5. Called from reset (twice), mon_reenter_704 and mon_enter_from_os.

### mg_init_machine sub_01000c9c(sid, mg) -> d0 = nvram-was-invalid
Called from sub_01000e2e, mon_init (not on reinit) and sub_0100ac8a.
* bzero(mg+$144, $2E) (km struct), bzero(mg+$1AA, $20) (mg_addr), mg+$1CA = 0 (mg_na), mg+$1A8 = 'l' (mg_fmt), mg+$192 = $10 (mg_radix), mg+$6 = sid, mg+$318 = mg+$31C = 0 (console_i/o), mg+$194 = 0, mg+$3B2 = 0.
* mg+$3A9 (board rev) = SCR1 bits 11:8, read from $0200C002 or, when type reads 4, from **$02200002**. mg+$3CA = mg+$3CE = 0.
* **mg+$194 = $139 for machine types 0, 1, 2 only** (and BMAP ptr mg+$3B2 = $020C0000 for types 1,2). The v66 listing sets +$194 = $139 and +$198 = $136 next to each other; these are NetBSD's `MG_dmachip` (404) and `MG_diskchip` (408): 0x139 = "313" = the original NeXT DMA/memory-controller chip set. **Every `cmpi.l #$139,$194(mg)` therefore means "original (non-colour, non-Turbo) memory system?": not-$139 selects the TMC/colour-controller register set (video interrupt $02200080, NMI $02200020, parity regs $02200004..C, ADB init, VRAM at $0C000000, 32 MB bank stride).** Turbo Color never has $139.
* Type dispatch through the table at $01011bf0 (12 longs, decoded as code by the generator): 0->sub_01000d6c, 1->d64, 2->d6c, 3->d7a, 4,5->d96, 6,7->d86, 8,9->dbc, A,B->dac. Fields: mg+$3B6 = 1 for stations (1,3,4,5,6,7) else 0 (drives "Backplane slot #%d" and the panel layout); mg+$3BA = 0 for types 0-2, 1 for all others (memory-system generation: selects sizing routines and SIMM tables); mg+$3BE = 2 for types 3..B (SIMMs per bank: pairs; 0 for the 4-SIMM-bank originals); types 4-7 also clear mg_sid; types 6,7,A,B set mg+$3CA = $02210000 (NCC) and mg+$3CE = $03E00000 (cache tag RAM). **TC (type 5): +$3B6 = 1, +$3BA = 1, +$3BE = 2, +$6 = 0, no NCC.**
* NVRAM: d2 = sub_0100861c(nvram) (reads 32 RTC bytes via sub_010087cc, verifies the checksum word at +$1E; 0 = ok). If ok and nvram byte 0 bits 7:4 (`ni_reset`) == 9 the copy is accepted. Otherwise a default is built: bzero 32; reset field = 9; brightness (bits 14-19) = $3D; byte 14 POT = $11 (POT_ON \| TEST_DRAM); bootcmd (bytes 18..) = "en"; volume right (bits 20-25) and volume left (bits 4-9) = 0; byte 0 bit 2 (allow eject) set. Returns d2 (non-zero = NVRAM was uninitialised).

### mon_show_test_panel sub_01000e2e(mg) -> mg_flags value
Calls mg_init_machine(sid, mg). If nvram POT & $11 (POT_ON or TEST_DRAM): `sub_01004440(0x154, 0x134, sub_01015f74)` (draw the panel image at x=340,y=308; sub_01015f74 is 28 bytes of image data, mis-decoded as code), `sub_010077a4(0x226, 0x186, 1, "Testing\nsystem ...")` (text at 550,390), then a second image chosen by mg+$3B6 (0 -> sub_01015040 cube icon, 1 -> sub_01015264 station icon) at (0x280, 0x161), returns $80; else returns 0.

### mon_init sub_01000ec6(sid, mg, reinit, dotests)   [2486 bytes]

1. mg+$1A0 = $02007800 (intrmask ptr), mg+$19C = $02007000 (intrstat ptr).
2. Not reinit: mg_set_ptr(mg); nvram flag = mg_init_machine(sid, mg); callbacks mg+$2D6 = sub_01008140 (getc), +$2DA = sub_01008184 (try_getc), +$2DE = sub_010081c8 (putc), +$2E2 = sub_0100ab7c (alert), +$2EA = sub_01007dd6 (alloc); mg+$312 = 3, +$30A = 3, +$30C = $4A (74); mg+$314 = $01000008 (ROM Ethernet address); mg+$A = $2000 (pagesize); mg+$2F2 = $0211A000 (event counter); mg+$2F6 = 0; mg+$3AA = sub_010008e2; mg+$3AE = 0.

## 5. Uncertainties and generator issues

* SCR2 bit 12 ($1000) gating the TMC video timing write, and bits 11/12 set by the cube-030 path: meaning not established (Previous does not define them).
* The colour TMC timing fields (display 208 / 624) do not decode with the same unit as the mono values (280 / 832 = 1120/4, 832); unit unknown.
* The "VRAM" text check at loc_010011b8 is inferred to come from sub_01003a9c (called at $0100054e); not verified.
* mg+$30A/$30C/$312 naming (major/minor/seq) is taken from the brief; the banner printf that uses them is outside this range.
* mg+$3BE = "SIMMs per bank" and mg+$3BA = "memory generation" are interpretations of the values, not names from source.
* Data decoded as code by the generator (all referenced from this range): jump tables sub_01011bf0 (12 longs), sub_01011c20 (8 longs), dat_01011c40 ($35 longs, command table); string-pointer tables dat_010149e4 and sub_01014a24 (16 longs each); size tables sub_01014a64 / dat_01014aa4 (16 longs each); byte tables dat_01014ae4 (4), sub_01014ae8 (8), dat_01014af0 (4), dat_01014af4 (4); dat_01014af8 (5-byte rows, at least 26 rows); image data sub_01015040, sub_01015264, sub_01015f74; vbr tables dat_010145b0/dat_010145bc (8 longs each, only slot 2 used).
* $010007b8..$010007c5 (`rts; movea.l #2,a7; bsr.l $010040e6`) is unreachable dead code, not a mis-decode. $01000c9a is a nop pad.
* sub_01000728 reads with a plain `move.w` instead of `moves.w` (original ROM quirk).
