# ROM range $0100A000 .. $0100BFFF (listing lines 16467..20201)

Contents of this range, in order:

1. Keyboard input through the KMS chip at `$0200E000` (`sub_0100a00e` .. `sub_0100a520`).
2. The graphics text console: 8x12 font, cursor, scrolling (`sub_0100a56c` .. `sub_0100aa76`).
3. Alert / "Error during boot" printing (`sub_0100ab1e` .. `sub_0100aba4`).
4. Boot-time display selection, NeXTbus display-board probing and the board-ROM code
   interpreter (`sub_0100abdc` .. `sub_0100b7b0`). Only the on-board path matters for a Station.
5. The display driver table (`$0101B080`) and the three built-in drivers: colour 1120x832,
   colour 832x624 and mono 1120x832, including the complete Bt463 RAMDAC programming
   (`sub_0100b7c0` .. `sub_0100bf9e`).

All routines get the mg pointer either from `sub_01000686` (`movec vbr,a0; move.l 4(a0),d0`:
mg pointer stored at vbr+4, i.e. at mg+$404 since vbr = mg+$400) or as first stack argument.

## KMS keyboard routines

Register layout used (kms.c): `$0200E000` status long: byte1 bit6 (long bit 22) = KM data
received, byte1 bit5 (bit 21) = KM overrun (write 1 to clear); `$0200E002` byte bit1 = KMS enable;
`$0200E003` = command byte; `$0200E004` = command data long; `$0200E008` = KM data long
(byte0: bit6 no-response, bit5 user poll, bit4 invalid/master, bits3..0 device address (bit0 = mouse);
byte2 bit7 key valid, bits6..0 modifiers (bit0 ctrl, bit1 L-shift, bit2 R-shift, bit3 L-cmd, bit4 R-cmd,
bit5 L-alt, bit6 R-alt); byte3 bit7 key up, bits6..0 keycode).

### sub_0100a520 kms_send_cmd(cmd byte at 8(a6)+3, data long at $C(a6))
If mg+$170 bit7 clear: `ori.b #$2,$0200E002` (KMS_ENABLE) and set the bit. Then
`$0200E003 = cmd`, `$0200E004 = data`, delay 100 us. Callers: `$0100569e`, `$010056cc`,
`$01009946`, `sub_0100a2ba`, `sub_0100a4da`; also in pointer tables at `$010056fe`, `$01009886`.

### sub_0100a4da kms_send_cmd_wait(cmd, data)
kms_send_cmd, then poll `$0200E001` bit6 (KM_RECEIVED) up to 100000 iterations.
Returns 0 on response, `$40000000` on timeout. Callers `$010098d6`, `$0100991a`, `$01009936`
(keyboard init) and `sub_0100a2ba`.

### sub_0100a00e kms_poll_km_event()
Returns 0 immediately if mg+$3E5 bit0 (interrupt mode). Reads `$0200E000`; if neither bit22
(received) nor bit21 (overrun) is set returns 0. If overrun: `ori.b #$20,$0200E001` clears it.
Copies `$0200E008` to mg+$144. If the event is a key-down (byte3 bit7 clear) or the device
address nibble is non-zero: mg_flags |= 2 and return 1; else return 0.

### sub_0100a06c kms_event_pending()
Interrupt mode: dequeue into mg+$144 via `sub_0100d032`, return 1. Polled mode: return
mg_flags bit0 (and clear it).

### sub_0100a0ac con_flow_control_poll(key word at $A(a6))
Called from `vid_console_putc` while output is paused. If `kms_poll_km_event`: translate with
`kms_read_key`; `$13` (^S) sets mg+$170 bit2 (pause), `$11` (^Q) clears it, `$100` (no char)
ignored, anything else sets mg_flags bit0 and clears bit2.

### sub_0100a118 vid_console_putc(word at $A(a6), char at $C(a6))
Called from `$010081fe` (console putc dispatcher). If mg+$170 bit0 clear: call `sub_010098a4`
(KMS init; returns 0 -> return 0), and if bit3 set open the console window `sub_01009a2c(0,0,0)`.
If bit3 set: while mg+$170 bit2, `con_flow_control_poll`; if char == $A first `vid_putc($D)`;
`vid_putc(char)`. Returns 1.

### sub_0100a1a8 kms_power_key_check()
24 callers (monitor idle loops). If interrupt-status bit2 (INT_POWER) is set and RTC reg $30
reports the power button (`sub_010082ca`): if console open (mg+$170 bit3) print
`"\nreally power down? "` and read a key (interrupt queue or `kms_translate_key`); a `y`
(or no console) powers off: wait for the button release, `sub_0101027e(0,1)`, `sub_01010700(0)`,
`sub_01008380` (RTC power off), then `bra.b *` forever. Any other key: echo it, clear
mg_flags bit0, wait for release, return $A. Without a power request: in interrupt mode
dequeue + translate one key and return it, else return 0.

### sub_0100a2ba kms_read_key(word at 8(a6))
Interrupt mode (mg+$3E5 bit0): set mg+$3AE bit28, loop {dequeue; if none call
`kms_power_key_check`, return its value if non-zero}; translate and return.
Polled mode loop: `kms_power_key_check` (return if non-zero); `kms_send_cmd($C6, $01FFFFF6)`
(KMPOLL: poll mask, device addresses 0,1,F,F,F,F,F and speed 6); read `$0200E000`; if
bit22 not set and mg_flags bit1 clear, repeat. If bit1 set clear it (event already latched by
`kms_poll_km_event`), else latch `$0200E008` into mg+$144. If byte0 bit6 (no response) and
not bit4: `kms_send_cmd_wait($C5, $EF000000)` (KMREG, KM_CMD_SET_ADDR = reset the keyboard
address). If the device address nibble == 1 (mouse) return $100; else clear mg_flags bit0 and
return `kms_translate_key(&mg+$144)`.

### sub_0100a3a6 vid_console_getc()
Called from `$0100816a` (console getc dispatcher). Loops `kms_read_key` until the result is
not $100/$13/$11, clears mg_flags bit0, maps $D to $A.

### sub_0100a3f2 kms_translate_key(event*)
Returns $100 if byte2 bit7 (valid) is clear or byte3 bit7 (key up) is set. Index =
keycode*2 + (shift L|R ? 1 : 0) + (ctrl ? $A2 : 0) into the word table at `$0101A978`
(two 81x2 word tables: plain/shift, then ctrl versions; 324 words, ends at `$0101AC00`).
Values $101..$108 are special: value-$101 indexes the 8-entry table `$01011E78`
(verified against the ROM bytes: a47c, a4ca, a4ca, a4ca, a4ca, a4ca, a47c, a4ca), so
$101 (keycode 1) and $107 (keycode $19) go to `kms_key_brightness` (-1 for $101, +1 otherwise),
$102..$106 and $108 (keycodes 2, 9, $F, $10, $16, $1A: volume keys and arrows) return $100.
$100 (no key) and anything >$108 is returned as is.
`sub_0100a47c kms_key_brightness`: NVRAM read (`sub_0100861c`), brightness field
(byte +$17 {4:6}) +-1 clamped to 0..$3D, NVRAM write (`sub_0100866c`), then
`vid_driver_set_brightness(mg, value)` (colour: palette rescale, see below). Returns $100.

Decoded keymap (plain / shift; ctrl column differs only for letters -> control codes):
kc03 `\ |`, 04 `] }`, 05 `[ {`, 06 i, 07 o, 08 p, 0B keypad 0, 0C keypad ., 0D enter,
11 kp1, 12 kp4, 13 kp6, 14 kp3, 15 kp+, 17 kp2, 18 kp5, 1B delete ($7F, shift $08), 1C `= +`,
1D `- _`, 1E `8 *`, 1F `9 (`, 20 `0 )`, 21..25 kp7 8 9 - *, 26 `` ` ~ ``, 27 kp= ($7C shifted),
28 kp/ (`\` shifted), 2A return, 2B `' "`, 2C `; :`, 2D l, 2E `, <`, 2F `. >`, 30 `/ ?`,
31 z, 32 x, 33 c, 34 v, 35 b, 36 m, 37 n, 38 space, 39 a, 3A s, 3B d, 3C f, 3D g, 3E k, 3F j,
40 h, 41 tab, 42 q, 43 w, 44 e, 45 r, 46 u, 47 y, 48 t, 49 esc (`~` shifted), 4A `1 !`,
4B `2 @`, 4C `3 #`, 4D `4 $`, 4E `7 &`, 4F `6 ^`, 50 `5 %`; 00, 0A, 0E, 29 = $100.

## Graphics text console

Pixel addressing used everywhere: byte offset of pixel column x = x*4 / (mg+$324)
(x*32/ppl bits / 8), line offset = y * mg+$328. Character cells are 8x12 pixels; the font
is at `dat_0101AC00`: 96 glyphs ($20..$7F) x 12 bytes, MSB = left pixel; it ends exactly at
`$0101B080` where the driver table starts.

### sub_0100a63c vid_putc(char at $B(a6))
`vid_lock`; `vid_cursor_toggle` (erase cursor); dispatch on char - 7 through table `$01011E98`:
7 BEL `sub_0100a704` (bell on/off via `sub_01005758`), 8 BS `sub_0100a6a4`, 9 TAB `sub_0100a6b4`
(spaces to a multiple of 8), $A LF `sub_0100a69c` (row++), $B -> `loc_0100a71a` (ignored as < $20),
$C FF `sub_0100a6f2` (home + `vid_clear_text_area`), $D CR `sub_0100a678` (col = 0, first setting
mg+$170 bit8 and drawing the cursor if the bit was clear). Printable (`loc_0100a71a`): cell address =
mg+$368 + ((mg+$152 + col)*32 / ppl) + (mg+$150 + row) * 12 * mg+$328 (if col is negative the
column offset is -col*4/ppl instead); 12 rows from the font; per row the 8 bits select fg
(mg+$15C/$15E/$15F) or bg (mg+$160/$162/$163) and are written as: ppl == 16 (2 bpp): one
word holding 8 x 2-bit pixels (bit 7 of the font row -> the two most significant bits);
ppl == 4 (8 bpp): 8 bytes; ppl == 2 (16 bpp, colour): 8 words; ppl == 1 (32 bpp): 8 longs.
Then col++ (or col -= 8 when negative). Epilogue `loc_0100a8b2`: if col >= mg+$154: col = 0,
row++; if row >= mg+$156: row = rows-1 and scroll: for each of the (rows-1)*12 scan lines copy
the line 12 lines below it, width = (mg+$154 * 8 * 4 / ppl) / 32 iterations of a 32-long
Duff's device (`sub_0100a94c`..`sub_0100a98a`, table `$01011EB4`, index = longs & 31), then
`vid_clear_to_eol` for the last row. Finally `vid_cursor_toggle` (draw cursor) and `vid_unlock`.

`sub_0100a9ce vid_cursor_toggle`: if col >= 0, invert the 8x12 cell (`not.w` for 2 bpp, otherwise
`not.l` for 32/ppl longs per row). `sub_0100a56c vid_clear_text_area`: fills rows
mg+$150 .. +$150+$156 (x12 lines), columns $152 .. $152+$154, with mg+$160 (longs).
`sub_0100aa76 vid_clear_to_eol`: fills columns col..$154 of the 12 lines of the current row
with mg+$162 (2 bpp, words) or mg+$160 (longs). `sub_0100a5fa vid_clear_screen`: fills
mg+$368 with mg+$344 for (mg+$328 * mg+$334)/4 longs (whole visible frame buffer, dark grey).
All of these wrap the work in `vid_lock`/`vid_unlock`.

### sub_0100b2b2 vid_lock / sub_0100b2f4 vid_unlock
Nesting counter mg+$3A0. On the outermost lock: on-board display (mg+$34C == mg_sid) ->
driver op +$10 (`sub_010040a8` = `cpusha #1`, pushes the data cache so VRAM writes land);
board display -> run board code mg+$350. Unlock: driver op +$14 (nop) or board code mg+$354.
The `cpusha` implies the ROM writes VRAM with the data cache enabled (copyback) and pushes it
before letting the display read it; a core that treats VRAM as cacheable must honour `cpusha`.

## Alerts

`sub_0100ab1e mon_alert_printf(x, y, title, fmt, a, b, c)`: if mg+$170 bit3 clear: clear
mg_flags bit3 and `sub_01009a2c(x, y, title)`; set bit5; `printf(fmt, a, b, c)`.
`sub_0100ab7c mon_boot_error(fmt, a, b, c)` (installed at mg+$2E2 by `$01000f4e`):
`mon_alert_printf(0, 0, "Error during boot", fmt, a, b, c)`.
`sub_0100aba4 mon_alert_close`: if bit5: `sub_01009e9a`, mg_flags |= 8, clear bit5.

## Boot-time display selection: sub_0100ac8a vid_console_init(mg)

Called once from the reset/C init path at `$0100057c` (also in the pointer table at `$0100057e`).
Steps:

1. `sub_01000c9c(mg_sid, mg)`: re-initialise machine/device fields. d5 = mg_sid.
2. `sub_0100c626(mg)`: monitor sense (outside this range).
3. d3 = NVRAM byte $11: if bit5 (USE_CONSOLE_SLOT) d3 = CONSOLE_SLOT (bits 4:3) * 2, else -1.
4. d4 = `vid_find_driver(mg)`. If a built-in display answers (d4 != -1):
   `vid_driver_init(mg, d4)`, `vid_driver_setup_dac(mg)`, `vid_clear_screen`, delay 750 ms
   (`$B71B0` us), `vid_enable_display(mg)`. If d3 == mg_sid: d6 = d4.
5. NeXTbus scan, only if mg_sid == 0 and mg+$3B6 == 0 (cubes: types 0, 2, 8, 9, A, B). **Stations
   (type 5) skip this block entirely.** For cubes:
   * non-Turbo (mg+$194 == $139): `SCR2 ($0200D000) low word |= $80` (byte 3 bit7 = "ROM/local
     only" bit, Previous SCR2_ROM);
   * Turbo: `SCR2 low word &= ~$80` (clear byte 3 bit7), TMC control `$02200010 low word &= $FCFF`
     (clear bits 9:8, annotated "ROM-local"/"local-only"), GPIO `$02012000 = $88` (byte).
   * if mg+$3B2 (BMAP): `BMAP+4 &= ~$40`.
   * probe `$F0FFFFF0` (own NBIC id register); if readable and type is 0 or 2 (non-Turbo cubes):
     NBIC `$02020004 = $80000000` (ID valid), NBIC `$02020000 = $08000000` (store-forward).
     Delay 210 ms (`$33450` us).
   * for slot = 0, 2, 4, 6 except own slot: `nbus_probe_display_board(mg, slot)`; on success
     d5 = slot, d4 = mg+$34D and if slot == d3, d6 = d4. If d3 is a slot with no display, d3 = -1.
6. If d3 != -1 (NVRAM console slot found) d5 = d3, d4 = d6. If d5 == mg_sid:
   `vid_driver_init(mg, d4)` (re-init on-board display; note the DAC and enable steps are not
   repeated), else `vid_init_display(mg, d5, d4)`.
7. Restore mg+$170 (saved at entry).

For the Turbo Color station the effective sequence is therefore: `vid_probe_color_1120` ->
`vid_init_color_1120x832` (or the 832x624 variant) -> `dac_init_bt463` -> clear to dark grey ->
750 ms -> `vid_enable_display` (brightness clamp, palette, `$02200080 = $04000000`).

## Display driver table `$0101B080` (3 entries x 7 pointers, 28 bytes each; verified bytes)

| slot | index 0: colour 1120x832 | index 1: colour 832x624 | index 2: mono 1120x832 |
|---|---|---|---|
| +0 probe(mg) | `sub_0100b972` | `sub_0100b9a8` | `sub_0100bf72` |
| +4 init(mg, idx) | `sub_0100b9e6` | `sub_0100bb8e` | `sub_0100bf9e` |
| +8 setup DAC(mg) | `sub_0100bc78` | `sub_0100bc78` | `sub_0100c146` (nop) |
| +$C enable(mg) | `sub_0100be7c` | `sub_0100be7c` | `sub_0100c14e` (brightness reg `$02110000` from table `$0101B0D4`, `$02200080 = $04000000` on Turbo) |
| +$10 enter(mg) | `sub_0100c1aa` (nop) | `sub_0100c1aa` | `sub_0100c1aa` |
| +$14 exit(mg) | `sub_010040a8` (cpusha) | `sub_010040a8` | `sub_0100c1aa` (nop) |
| +$18 set brightness(mg, v) | `sub_0100bebe` | `sub_0100bebe` | `sub_0100c18a` |

Note: `sub_0100b8d8` (called by vid_lock) uses offset +$10 and `sub_0100b90a` (vid_unlock)
uses +$14, so for the colour drivers the lock is a nop and the `cpusha` happens at unlock,
i.e. after the text has been written. `sub_0100b7c0 vid_find_driver` calls +0 of entries
0, 1, 2 in that order and returns the first index whose probe returns 1 (-1 if none).
`sub_0100b85c vid_driver_init(mg, idx)`: bzero(mg+$324, $80), then +4(mg, idx) if 0 <= idx <= 2.
`sub_0100b8a6`, `sub_0100b8d8`, `sub_0100b90a`, `sub_0100b93c(mg, v)`: call +8, +$10, +$14,
+$18 of entry mg+$34D, only when mg+$34C == mg_sid (on-board display).
`sub_0100b802 vid_enable_display(mg)`: NVRAM brightness field < $14 -> set to $14 and write
NVRAM; then +$C(mg) if on-board.

### Probes
* `sub_0100b972` (index 0): type - 3 indexes table `$01011FDC` (verified bytes): type 3 -> 1;
  types 4, 6, 8, A -> 0; types 5, 7, 9, B -> `sub_0100b994`: 1 iff `$0200D002` (SCR2 byte 2)
  bit4 is set. Previous (sysReg.c line 210) initialises this bit to 1 on Turbo with the comment
  "video mode is 25 MHz". Types outside 3..B -> 0.
* `sub_0100b9a8` (index 1): types 5, 7, 9, B and SCR2 byte 2 bit4 clear -> 1, else 0.
  So on a Turbo Color the SCR2 byte-2 bit4 chooses 1120x832 (set) versus 832x624 (clear).
  The FPGA core should present bit4 = 1 to get the normal MegaPixel mode.
* `sub_0100bf72` (index 2): type - 3 indexes `$01012100`: 3, 5, 7, 9, B -> 0; 4, 6, 8, A -> 1;
  types outside 3..B (0, 1, 2) -> 1 (mono).

| +$34C | low byte of mg_sid (mg+9) | |
| +$34D | idx (low byte of the second argument) | |

So the ROM believes the Turbo colour VRAM holds 936 lines of 2240 bytes (= $1FFD00 of the
2 MB at `$0C000000`) and the non-Turbo one 910 lines of 2304 bytes.

**Pixel format (Turbo Color, from the grey values and the 16 bpp text path):** one 16-bit
big-endian word per pixel, `RRRR GGGG BBBB xxxx`: white = $FFF0, light grey = $AAA0, dark grey
= $5550, black = $0000. The low nibble is never set by the ROM (it is the unused/alpha nibble; the
Bt463 read masks below ignore the low 4 bits of every channel byte). Two pixels per long, the
left pixel in the high word.

### sub_0100bb8e vid_init_color_832x624(mg, idx)  [index 1]
16 bpp, +$328 = $680 (1664 = 832*2), +$32C = +$330 = $340 (832), +$334 = $270 (624), same
grey values, frame buffer `$0C000000` (Turbo) / `$2C000000`, size $FD800 (832 x 624 x 2),
free VRAM at base+$FD800 of size $102600 (total $1FFE00). Selected on Turbo colour machines only
when SCR2 byte 2 bit4 is clear. Which monitor/timing this corresponds to is not established
here (the TMC video timing written at reset does not depend on it; see the reset notes).

### sub_0100bf9e vid_init_mono_1120x832(mg, idx)  [index 2, continues past the range to $0100c144]
2 bpp (+$324 = 16), +$328 = $460/4 = 280 (Turbo) or $480/4 = 288, +$32C = 1120, +$330 =
1120/1152, +$334 = 832, white = 0, light grey = $55555555, dark grey = $AAAAAAAA, black =
$FFFFFFFF (`moveq #$ff` sign-extends), frame buffer `$0C000000` (Turbo mono) / `$0B000000`
(non-Turbo), size = 280*832 = $36400 / 288*832 = $3A800, free VRAM after it: 104 lines
(Turbo, $71C0) / 78 lines ($57C0). Mono is not the target but shows the 2 bpp convention
(0 = white .. 3 = black) reused by the text renderer.

## Bt463 RAMDAC programming

Address selection (both routines): Turbo: base `$0201C000`; non-Turbo colour (mg+$194 == $139):
`$02118100` (this is the `$02018100` RAMDAC of ioMemTabNEXT.c seen through the `$02100000`
mirror; the listing's "Serial Interface Clock" annotation for `$021181xx` is wrong).
Register use matches ramdac.c: +0 = address low byte, +1 = address high nibble, +2 = register /
window-type / cursor data (auto-increments), +3 = palette data (3 bytes per entry R, G, B,
auto-increments).

### sub_0100bc78 dac_init_bt463(mg)   (driver op +8)
1. Only for machine type 3 (non-Turbo colour): `SCR2 $0200D000 low word |= $80` and
   `BMAP+4 &= ~$40`. Nothing of this on Turbo.
2. d4 = brightness scale = NVRAM brightness (0..$3D) * 64 / 61.
3. Control registers, written as (addr low, addr high = $02, data) in this order:

   | addr | register (ramdac.c) | value |
   |---|---|---|
   | $201 | CR0 | $40 |
   | $202 | CR1 | $00 |
   | $203 | CR2 | $80 |
   | $205 | read mask 0 | $F0 |
   | $206 | read mask 1 | $F0 |
   | $207 | read mask 2 | $F0 |
   | $208 | read mask 3 | $F0 |
   | $209 | blink mask 0 | $00 |
   | $20A | blink mask 1 | $00 |
   | $20B | blink mask 2 | $00 |
   | $20C | blink mask 3 | $00 |

   (The meaning of the CR0/CR1/CR2 bits is not derivable from ramdac.c, which only stores them;
   from the Bt463 data sheet CR0 $40 and CR2 $80 select the pixel multiplex mode / sync options.
   Unverified here.)
4. Window type table: for addr = $300..$30F: addr low = $00..$0F, addr high = $03, then three
   data writes $00, $01, $00 -> every one of the 16 window types = $000100.
5. Palette entries 0..255: addr low = i, addr high = 0, then three writes to +3 of the same
   value v(i) = min($FF, (gamma[i] * d4) >> 6 + 8), gamma = the 256-byte table at `$01012000`.
6. Palette entries $100..$1FF: identical values (the table is addressed as `$01011F00 + i` with
   i = $100..$1FF, i.e. the same 256 bytes) -> the second half mirrors the first.
7. Palette entries $20C..$20F (overlay/cursor colours): R = G = B = $FF.

Gamma table `$01012000` (256 bytes): 00 10 17 1c 20 24 27 2a 2d 30 32 35 37 3a 3c 3e 40 42 ...
ff; at the 16 positions a 4-bit component actually reaches (index n*16, because the read
masks are $F0): 00 40 5a 6f 80 8f 9c a9 b5 c0 ca d4 dd e6 ef f7. The Bt463 uses a
separate lookup per channel, so a pixel nibble R selects palette entry R<<4 of the red column,
etc. At maximum brightness ($3D -> d4 = 64) an output component is gamma[n*16] + 8, e.g. nibble
$F -> $FF, $8 -> $BD, $0 -> $08. The entries 0..255 are all grey (R = G = B).

### sub_0100bebe dac_set_brightness_palette(mg, brightness)   (driver op +$18, and from +$C)
Same address selection; d4 = brightness * 64 / 61 (signed divide); rewrites palette entries
0..255 only, with the same formula (addr low = i, addr high = i >> 8 = 0, three writes of v(i)).
Called on every brightness key press through `kms_key_brightness` -> `vid_driver_set_brightness`.
So on colour machines the brightness keys never touch the `$02010000` brightness register;
brightness is implemented by rescaling the RAMDAC palette.

### sub_0100be7c vid_color_enable(mg)   (driver op +$C)
`dac_set_brightness_palette(mg, NVRAM brightness)`, then non-Turbo: `move.b #$4, $02118180`;
Turbo: `move.l #$04000000, $02200080` (TMC video interrupt/enable register, byte 0 = $04 =
"enable" per the tmc.c annotation). This is the only place in the range that turns the Turbo
video output on; it happens 750 ms after the screen was cleared to dark grey.

## NeXTbus display boards (cubes only; skipped on stations)

`sub_0100ae26 nbus_probe_display_board(mg, slot)`: reads `$F0FFFFF0 | slot<<24` (must be
readable and have bits 31:30 == 11), then `$F0FFFFE0 | slot<<24` (top byte must be $A5);
bzero display struct, mg+$34C = slot, +$34D = 0, +$34E = byte lane width read at `$F0FFFFD8`
(must be 1, 4 or 8); ROM address = bytes at `$F0FFFFB8` (top byte of the long), `$F0FFFFC0`,
`$F0FFFFC8`, `$F0FFFFD0`; if its top byte is $F0 it is slot-relative (slot << 24) else board
space (slot << 28); stored in +$35C and +$358. Then descriptor count n = ROM long 1; for
descriptor i (ROM long index 2 + 5*i, i < n): run its code with `nbus_run_boardcode`; if it
returns 1: `vid_init_display(mg, slot, i)`, `vid_clear_screen`, `vid_post_init(mg)`, return 1.
`sub_0100b04e vid_init_display(mg, slot, idx)`: on-board -> `vid_driver_init`; board -> +$34E,
ROM address windows, +$360 = ROM long 0 * lanes * 4, +$350/+$354 = ROM longs 2*idx+4 / +5,
parameter block pointer p = ROM long 2*idx+6: +$324..+$348 from p+0..p+9 (same layout as the
built-in drivers), five more windows into +$358+12*i from p+10.., +$338 |= 1, and if +$378 == 0:
+$374 = `$04100000`, +$378 = $100000 (1 MB scratch in DRAM). `sub_0100abdc nbus_rom_read_long(n)`
assembles the long from 1, 4 or 8 byte-lane bytes. `sub_0100b338 nbus_map_addr` and
`sub_0100b38c nbus_run_boardcode` (the little RISC-like interpreter, opcodes listed in the
names file) exist only for such boards; they are irrelevant for the Turbo Color station.

## Descent / generator remarks

* Pointer and data tables inside the range or referenced from it that are decoded as code:
  `$01011E78` (8 longs), `$01011E98` (7), `$01011EB4` (32), `$01011F34` (42), `$01011FDC` (9),
  `$01012100` (9), `$01012124` (6), `$01011BF0` (12): all `dc.l` pointer tables; the leading
  entries appear as `btst.l d0,d0` pairs. `$01012000..$010120FF` is the 256-byte gamma table
  (labelled `sub_01012000`, `dat_01012046`, `sub_01012080`). `$0101A978..$0101ABFF` is the
  324-word keymap (`sub_0101a978`). `$0101B080..$0101B0D3` is the 3 x 7 pointer driver table
  (partly in `unreached-linear.asm` as a gap), `$0101B0D4..$0101B113` a 64-byte mono brightness
  table.
* `sub_0100a94c`..`sub_0100a98a` (32 labels) and `sub_0100a678`..`sub_0100a704`,
  `sub_0100a47c`, `sub_0100b3ee`..`sub_0100b7b0`, `sub_0100b994`/`sub_0100b99e`,
  `sub_0100bf94` are not separate C functions but jump-table targets inside `vid_putc`,
  `kms_translate_key`, `nbus_run_boardcode`, `vid_probe_color_1120` and `vid_probe_mono`

  end to `$0100c144`.
* Uncertain: exact meaning of the Bt463 CR0/CR1/CR2 values; the monitor that the 832x624 mode
  serves; keycodes $02/$10/$16/$1A special values (assumed volume/arrow keys, ignored anyway).
