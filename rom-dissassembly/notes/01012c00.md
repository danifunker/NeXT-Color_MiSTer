# $01012C00..$0101B480 — the data region of Rev 3.3 v74, and a v66 comparison

Everything from `$01012C00` to the end of the ROM (`$0101B47F`) is data. The recursive
descent seeded routines from every ROM pointer it found, so many table entries whose
first field is a pointer were labelled `sub_` (e.g. `sub_010145c8`, `sub_01015040`,
`sub_0101a354`) and bytes of image data that happen to be printable were labelled
`str_` (`str_01015657`..`str_01015c91`, `str_01016d3b`, `str_01016eb9`, `str_01017341`,
`str_01017387`, `str_010175d6`, `str_01017fef`, `str_0101820e`, `str_01018939`).
None of these are code or strings; the real layout is below. All decoding was done
on the binary with Python (`roms/Rev_3.3_v74.BIN`) and checked against the code that
indexes each table.

## 1. $01012C00..$01012C5B and the string block

### 1.1 Register names and bit descriptors (mis-decoded as `sub_01012c00`..`sub_01012c4a`)

Bytes:

```
01012c00 "0\0" "1\0" ... "7\0"          names shared by tbl_regs_d and tbl_regs_a (the command prefixes "d"/"a"/"" are dat_01013652/54/56)
01012c10 "pc\0" 01012c13 "sr\0"
01012c16 10 cf 02 't' 'r' 'a' 'c' 'e' 0e 's' 8e 'u' 0d 'm' 8d 'i' c9 03 'i' 'p' 'l' 05 'x' 04 'n' 03 'z' 02 'v' 01 'c' 00
01012c36 "usp\0" "isp\0" "msp\0" "vbr\0" "sfc\0" "dfc\0" "cacr\0"
01012c53 10 20 'd' 'e' 10 'i' 'e' 00
```

The descriptor format is the BSD kernel `%b` format as used by NeXT's printf
(`sub_01007772`, format `dat_010137c2`):

* byte 0 = output radix (0x10 = hex);
* then a sequence of fields: a control byte followed by the name (name ends at the next byte < 0x20 or >= 0x80):
  * `0x01..0x3F` = single bit, number is bit+1 (`0x0e s` = bit 13 = S);
  * `0x80|n` = single bit whose name is printed when the bit is **clear** (`0x8e u` = "u" when S is 0; `0x8d i` = "i" when M is 0);
  * `0xC0|n`, width = multi-bit field starting at bit n-1 (`0xcf 02 trace` = bits 15:14; `0xc9 03 ipl` = bits 10:8).

## 2. Monitor register tables $010145C8..$010148C0

All five tables use the same 20-byte entry, zero-terminated:

```c
struct regent { char *name; long where; long (*handler)(int mode, long base, struct regent *, char *input);
                char *bitdesc; long pad; };
```

`where` is an offset into the exception frame built by `loc_010005ae` (pointed to by
the `d`/`a`/`r` command argument, pushed as `$8(a6)` in `sub_01001ffe`/`sub_01002012`/`sub_01002026`)
for the CPU tables, or an absolute device address for the system-register tables.
`handler` is `mon_param_sysreg` (`sub_0100274e`) when the value must be shown with a
bit description; NULL means the generic longword show/edit in `loc_0100218a`.

| table | entries (name : where : handler : bitdesc) |
|---|---|
| `tbl_regs_d` 010145c8 (used by `sub_01002012`, prefix "d") | 0:+00 1:+04 2:+08 3:+0c 4:+10 5:+14 6:+18 7:+1c (d0..d7) |
| `tbl_regs_a` 0101467c (`sub_01001ffe`, prefix "a") | 0:+20 1:+24 2:+28 3:+2c 4:+30 5:+34 6:+38 7:+3c (a0..a7) |
| `tbl_regs_ctl` 01014730 (`sub_01002026`) | pc:+86, sr:+82 (`mon_param_sysreg`, `bits_sr`), usp:+40, isp:+44, msp:+48, vbr:+54, sfc:+4c, dfc:+50, cacr:+5c (`mon_param_sysreg`, `bits_cacr`) |
| `tbl_sysreg_old` 010147f8 | intrstat:$02007000 `bits_intr_old`; intrmask:$02007800 `bits_intr_old`; scr1:$0200C000 `bits_scr1_old`; scr2:$0200D000 `bits_scr2_old` (all `mon_param_sysreg`) |
| `tbl_sysreg_new` 0101485c | intrstat:$02007000 `bits_intr_new`; intrmask:$02007800 `bits_intr_new`; scr1:$0200C000 `bits_scr1_new`; scr2:$0200D000 `bits_scr2_new` |

So the exception frame layout (from these offsets) is: d0-d7 at +0, a0-a7 at +0x20,
usp +0x40, isp +0x44, msp +0x48, sfc +0x4c, dfc +0x50, vbr +0x54, cacr +0x5c, then the
68040 exception frame: sr (word) at +0x82, pc at +0x86, format/vector at +0x8a.

`mon_cmd_s` (`sub_01002168`, the `s` command) selects `tbl_sysreg_old` when
`mg+$194 == 0x139`, otherwise `tbl_sysreg_new`. `mg+$194` is set to `0x139` at
`$01000d32`/`$01000d3c` for machine types 0..3 (non-Turbo) and left 0 for Turbo
types 4..B, so **on the Turbo Color the `s` command uses `tbl_sysreg_new`**.
(v66 has only the old table.)

`mon_param_sysreg(mode, base, entry, input)` (`sub_0100274e`):
* address = base + entry.where; special case: if `entry.where == $0200C000` and
  `SCR1[15:12]` (read from `$0200C002`) == 4 the address becomes `base + $02200000`
  (the TMC copy of SCR1). Note the test is `== 4` only, like the reset code — for
  a type-5 board the `s scr1` command reads `$0200C000`.
* mode 0: `printf(dat_010137c2, *addr, bitdesc)` (value in hex followed by the `%b` expansion);
* mode 1: parse `input` with `sub_01007cd8` (radix 16), verify with `sub_010024f6` (password), store the long.

## 3. The `p` command parameter table $010148C0..$010149C4 (`tbl_params`)

Driven by `sub_0100213a` (command `p`) -> `sub_01002630(mg, tbl_params, mg_nvram=mg+$16, prefix)`,
which walks the table, calls each handler with mode 0 (show) then mode 1 (edit)
and afterwards writes the NVRAM back (`sub_0100866c`). Entry (20 bytes):

```c
struct param { char *prompt; long mask_or_offset; long (*handler)(int mode, u_char *nvram, struct param *, char *input);
               long maxlen; long pad; };
```

Handlers (all in the C monitor, outside this range):

* `mon_param_pot_bit` (`sub_0100287c`): NVRAM **byte 14** (`ni_pot[0]`, offset `$e` from `mg+$16`); shows "yes"/"no" (`dat_010137e5`/`dat_010130f8`) for `byte14 & mask`; on edit `y`/`Y` ORs `mask` (low byte, `$7(entry)`), `n`/`N` clears it, `.` keeps.
* `mon_param_reset_bit` (`sub_010029aa`): the 32-bit `ni_reset` long = NVRAM **bytes 0..3**; same y/n logic on the long. Clearing the eject bit (`mask == 0x04000000`) first calls `sub_0101034c` and refuses with "There must be a disk inserted in drive #0 before you can set" if no optical disk is present.
* `mon_param_parity` (`sub_0100291a`): NVRAM **byte 17 bit 2** (`USE_PARITY_MEM`, offset `$11`).
* `mon_param_bootcmd` (`sub_010027e2`): string at NVRAM + `mask_or_offset`, at most `maxlen`-1 chars ("must be < %d chars long"); `.` empties it.

| entry | prompt | value | handler | NVRAM location (rtcnvram.c 880-950) |
|---|---|---|---|---|
| 010148c0 | boot command | 0x12, len 0xc | `mon_param_bootcmd` | bytes 18..29 `ni_bootcmd[12]` |
| 010148d4 | DRAM tests | 0x10 | potbit | byte 14 bit 4 `TEST_DRAM_POT` |
| 010148e8 | perform power-on system test | 0x01 | potbit | byte 14 bit 0 `POT_ON` |
| 010148fc | \tsound out tests | 0x40 | potbit | byte 14 bit 6 `TEST_MONITOR_POT` |
| 01014910 | \tSCSI tests | 0x02 | potbit | byte 14 bit 1 `EXTENDED_POT` |
| 01014924 | \tloop until keypress | 0x04 | potbit | byte 14 bit 2 `LOOP_POT` |
| 01014938 | \tverbose test mode | 0x08 | potbit | byte 14 bit 3 `VERBOSE_POT` |
| 0101494c | serial port A is alternate console | 0x08000000 | resetbit | bytes 0-3 bit 27 (alt cons) |
| 01014960 | allow any ROM command even if password protected | 0x00000001 | resetbit | bit 0 (any cmd) |
| 01014974 | allow boot from any device even if password protected | 0x00000002 | resetbit | bit 1 (boot any) |

The tab-prefixed prompts are sub-options printed indented under "perform power-on

## 4. $010149C4..$01014CD8 : name, size, speed and memory-timing tables

### 4.1 `tbl_fcode_names` 010149c4 (8 longs) — used by `sub_0100223a` (`S [fcode]` command)
`"0","UD","UP","3","4","SD","SP","cpu"`, printed as `"Function code %d (%s)\n"` with fcode & 7.

### 4.2 SIMM type names (indexed by the 4-bit SIMM code of NVRAM bytes 10/11: size[1:0], page-mode bit 2, parity bit 3)
* `tbl_simm_names_nonturbo` 010149e4, 16 longs: no / 16MB of nibble mode / 4MB of nibble mode / 1MB of nibble mode / illegal / 16MB of page mode / 4MB of page mode / 1MB of page mode (illegal) / illegal / 16MB of parity nibble mode / 4MB of parity nibble mode / 1MB of parity nibble mode / illegal / 16MB of parity page mode / 4MB of parity page mode / 1MB of parity page mode (illegal). Used at `$01001068` and `sub_0100203a` (`m` command, non-Turbo path).
* `tbl_simm_names_turbo` 01014a24, 16 longs: no / 32MB of page mode / 8MB of page mode / 2MB of page mode / illegal / 32MB of page mode / 8MB / 2MB / illegal / 32MB of parity page mode / 8MB of parity page mode / 2MB of parity page mode / illegal / 32MB of parity page mode / 8MB / 2MB. Used at `$01001244` and `$010020a2` (Turbo `m` command: "Memory sockets %d and %d (%s) have %s SIMMs installed (0x%x-0x%x)").

### 4.3 SIMM size tables (longs, indexed by SIMM code)
* `tbl_simm_size_nonturbo` 01014a64: `{0, 0x01000000, 0x00400000, 0x00100000}` x4 (16 MB / 4 MB / 1 MB per 4-SIMM bank, page/parity bits ignored).
* `tbl_simm_size_turbo` 01014aa4: `{0, 0x02000000, 0x00800000, 0x00200000}` x4 (32 MB / 8 MB / 2 MB per SIMM pair). Used by the memory sizing code at `$010022f8`, `$0100302c`, `$0100328a` (bank base = `$04000000 + bank*size`, Turbo 32 MB stride) and `$0100123c`.

### 4.4 Speed tables (bytes)
The "CPU MC68040 %d MHz, memory %d nS" banner (`$01001462`) is computed from the raw SCR1
low byte kept in the local `-$1(a6)` of `sub_01000ec6`:

| table | index | values | selected when |
|---|---|---|---|
| `tbl_cpu_mhz_old` 01014ae4 | SCR1[2:0] | 16,20,25,33,40,50,66,80 | `mg+$194 == 0x139` (types 0-3) |
| `tbl_cpu_mhz` 01014ae8 | SCR1[2:0] | 40,50,66,80,16,20,25,33 | Turbo (cspd 7 = 33 MHz, matches tmc.c) |
| `tbl_mem_ns_old` 01014af0 | SCR1[5:4] | 100,100,80,60 | types 0-3 |
| `tbl_mem_ns` 01014af4 | SCR1[5:4] | 60,70,80,100 | Turbo (matches tmc.c: 0=60ns .. 3=100ns) |

Result goes to `mg+$3c2` (CPU MHz); if `mg+$3ca` (NCC pointer) is non-zero it is
forced to 40 (`$0100142e`) — the NCC boards (types 6,7,A,B per the jump table
`sub_01011bf0`: 0->d6c 1->d64 2->d6c 3->d7a 4,5->d96 6,7->d86 8,9->dbc A,B->dac) are
the 40 MHz "Nitro" machines. The Turbo Color (type 5) prints 33 MHz.
The same jump table sets `mg+$3b6` = 1 for station form factor (types 1,3,4,5,6,7)
and 0 for cubes, which selects the boot icon (section 5.2).

### 4.5 `tbl_memtiming` 01014af8 — 96 x 5 bytes (`dat_01014af8`)

Reset code (`loc_0100017e` for type 0, `loc_01000224` for types 1 and 2) computes

```
idx = (SCR1[1:0] << 2) | SCR1[5:4] | (SCR1[15:12] << 5) | 0x10      ; i.e. type*32 + cspd*4 + mmss with cspd in 4..7
a0  = 01014af8 + idx*5 ; copy 5 bytes to $02106010..$02106014 ; then clr.l $02004188
```

and the C routine at `$0100308c` repeats it with the full 3-bit cspd
(`type*160 + (cspd*4 + mmss)*5`) for types <= 2. `$02106010` (`$02006010` in
`ioMemTabNEXT.c`, "unhandled/trace") is the NeXT Computer/non-Turbo memory-timing
register block. **Turbo types (4..B) never touch it** (they go to `loc_010002a6`),
so the table is irrelevant to the Turbo Color core. Decoded (only the cspd 4..7
rows are reachable from the reset path; the others are reachable from `$0100308c`):

```
type 0 (NeXT Computer):  cspd5 mem0: 19 28 08 10 00   cspd5 mem1: 31 38 68 0d 00
                          cspd6 mem0: 1a 28 00 10 00   cspd6 mem1: 3e 78 00 0c 00   (cspd1/2 rows identical; all others 00 00 48 00 00)
type 1 (station) and type 2 (cube 040), identical blocks:
   cspd0/3/4/7 (any mem): 02 28 08 10 00 (mem0,1)      mem2,3: 00 00 48 00 00
   cspd1/5:  19 38 68 10 00 / 06 24 68 10 00 (mem0,1)
   cspd2/6:  1a 78 60 10 00 / 07 64 60 10 00 (mem0,1)
```

The default/filler entry is `00 00 48 00 00`. The table ends exactly at the help
text (`01014cd8`); the type-3 block would run into it, which is why only types
0..2 use the copy at reset (type 3 = colour station goes to `loc_0100027a`).

## 5. $01014CD8..$0101B480

### 5.1 Help text and VRAM letters
* `str_help` 01014cd8, 1096 bytes, "NeXT ROM monitor commands:\n\tp ... Copyright (c) 1988-1990 NeXT Inc.\n\n", printed by `sub_01002c3c` (`?` command). Byte-identical to v66 apart from location.
* `tbl_vram_ic_letters` 01015030, 16 bytes `"DHL\0CGK\0BFJ\0AEI\0"`: indexed by the failing byte lane in the VRAM test (`$01003c2a`/`$01003c52`, `sub_01003a9c`) to print "IC U%d" in `"\nVRAM failure at 0x%x:  read 0x%08x, expected 0x%08x, bad bits %08x, IC U%d\n"` (three chip designators per lane, first char used).

### 5.2 Images (01015040..010195F2)

All images are 2-bit-per-pixel greyscale (NeXT convention 0 = white .. 3 = black),
rendered by `vid_draw_image` (`sub_01004440`, args `(x, y, image*)`):

```c
struct image { char type;      /* 'B', 'U' or 'S' */  char pad[3];
               long width;     /* pixels */            long height;
               u_char data[]; };
```

* `'U'` (`vid_draw_raw_image`, `sub_0100457a`): raw rows, 4 pixels per byte MSB first, `width/4` bytes per row.
* `'B'`: run-length pairs `(count, value)` — count in 4-pixel groups, value = one byte of 4 pixels. Not used by any ROM image.
* `'S'` (`vid_draw_tbl_rle_image`, `sub_0100471c`): dictionary RLE: `n`, then `n` pairs `(value, count)`, then one dictionary index byte per run until the row is full; `height` rows.

Pixels are expanded through the 4-entry palette at `mg+$33c` according to the pixel
mode `mg+$324` = pixels per longword: 16 (2 bpp packed, mono), 4 (8 bpp), 2 (16 bpp,
**the Turbo Color / NeXTstation Color frame buffer**), 1 (32 bpp). `mg+$330`/`mg+$328`
are row strides, `mg+$368` the drawing base and `mg+$374` a second buffer (names/01004000.py calls `$374` the visible frame buffer; from the glyph copy in `vid_draw_char`, which reads the rendered sheet at `$374` and writes text at `$368`, `$374` looks like the off-screen sheet buffer — unresolved),
`mg+$340` the background fill value. Every image was decoded to its exact extent:

| address | type | size | bytes | end | what (from the animation script and an ASCII render) |

### 5.6 `tbl_bigfont_metrics` — the proportional boot font

`vid_draw_char` (`sub_010074b2`, char in `$b(a6)`) indexes `0101a4d0 + 6*c`. Chars
below 0x20 are never drawn (`'\n'` adds 20 to the y cursor `mg+$1d2` and resets x from
the saved value in `mg+$1ce`), so the real table is `0101a590` (' ' = all zero)
..`0101a7ca` ('~'); the base overlaps the end of `tbl_bootanim` harmlessly.

```c
struct glyph { u_char x;      /* x in the 256x50 glyph sheet (img_bigfont_sheet) */
               u_char top;    /* source row = 60 - h - top, relative to mg+$374 */
               u_char w, h;   /* pixels */
               char   yoff;   /* baseline offset added to the y cursor */
               u_char pad; };
```

Examples: `'!'` = 94 14 02 0e 00 00 (x 148, w 2, h 14), `'"'` = dc 0d 03 05 f7 00 (h 5,
yoff -9), `'$'` = b0 12 09 10 02 00, `'|'` = da 00 01 12 04 00 (w 1, h 18). The
glyph is copied pixel-wise from the off-screen buffer `mg+$374` (where
`vid_printf_at` rendered `img_bigfont_sheet` with interrupts masked, `sub_010043fc`)
to the frame buffer, in the pixel mode `mg+$324`. Line height 20 px.

### 5.7 0101A890..0101A978
* `str_hexdigits` 0101a890 "0123456789abcdef" — `sub_01007d6e` (number parser) uses `index(str, c) - str` as the digit value (so uppercase hex is not accepted here).
* `tbl_month_days` 0101a8a2, 13 words: 0, 0, 31, 59, 90, 120, 151, 181, 212, 243, 273, 304, 334 — cumulative days before month 1..12, used by the RTC date routine at `$01008474` (`(a0, month*2)` + day).
* `tbl_parity7` 0101a8bc, 128 bytes: 0x80 where the 7-bit index has odd parity; `$01008d4c` ORs it into the byte sent to the keyboard/mouse microcontroller (`d3 | table[d3 & 0x7f]`).
* `tbl_scc_clocks` 0101a93c: longs 3,684,000 and 4,000,000 Hz; `$01008b30` computes the SCC baud constant `clock/(2*16*baud) - 2` for each (`$02118004` = SCC channel).
* `ops_kms` 0101a944 (see 5.5).
* `ops_en2` 0101a95c (see 5.5), then `enet_addr_unset` 0101a974 = FF FF FF: `sub_01000ec6` (`$010013d2`) and `$01001af6`/`$01008ff8` compare it with ROM bytes `$0100000b..d` (MAC bytes 3..5): if the ROM MAC's low three bytes are all FF the address is taken from `mg+$4` instead of the ROM header.

### 5.9 Console backends, brightness, ADB
* `tbl_console_backends` 0101b080: 3 records of 7 longs (`0100b7d4`: stride 0x1c): [0] = {0100b972, 0100b9e6, 0100bc78, 0100be7c, 0100c1aa, 010040a8, 0100bebe}, [1] = {0100b9a8, 0100bb8e, 0100bc78, 0100be7c, 0100c1aa, 010040a8, 0100bebe}, [2] = {0100bf72, 0100bf9e, 0100c146, 0100c14e, 0100c1aa, 0100c1aa, 0100c18a}. `sub_0100b7c4` calls `fn[0]` of each in turn until one returns 1 and stores the index in `mg+$34d`; `$0100b83a` calls `fn[3]`(`$c` = set brightness) of the selected one. `0100b972`/`0100bf72` dispatch on machine type 3..B through pointer tables `sub_01011fdc`/`sub_01012100`; entry 2 is the one whose brightness routines (`sub_0100c14e`/`sub_0100c18a`) write the brightness register, so it is the Turbo/ADB backend (uncertain which of 0/1 is the non-Turbo KMS keyboard vs. serial console).

* `tbl_adb_dispatch` 0101b114: 8 longs {0100d9aa, 0100d9aa, 0100c788, 0100d9aa x5}, indexed at `$0100c338` by `(a2)` after reading `$02208080`/`$02208088` (ADB registers, Turbo only).

### 5.10 Optical drive tables 0101B1D8..0101B3D4
* `tbl_od_status` 0101b1d8: 60 x 6 bytes `{u8 flags; u8 0; char *msg}` indexed by the drive status code 0..0x3b (`mg-struct byte $4273`, `$0100f906`). `flags` bits 7:5 = recovery action (`bfextu {0:3}`, compared with 2; 0 = none, 1 = retry, 2 = restore, 3 = re-spin, 4 = give up), low bits = further flags (seen: 2d, 29, 0d, 4c, 80, 60, 20, 21). Only five codes carry a message: 0x03 "uncorrectable ECC error" (29), 0x04 "sector timeout" (2d), 0x10 "media upside down" (60), 0x14 "no disk inserted" (20), 0x1f "PLL failed" (2d); actions by code: 09/0f/11 -> 0 (ignore), 0a/1d/1e/20/21/23/24 -> 2 (restore), 10/22/2d-30 -> 3 (re-spin), 0b/2b/31-35 -> 4 (fail), all others -> 1 (retry).
* `tbl_od_drives` 0101b340, 48-byte record(s) indexed by `mg-struct byte $210a` (`3*idx*16`, `$010100c0`, `$0100f1d0`): `"Canon OMD-1"` (16 bytes), 8 zero bytes, longs 0x0003C460 (247,904 user blocks), -1, -1, 0x400 (1024-byte blocks), 0x40000 (262,144 physical blocks = 256 MB), words 0000 1035 0010. `od_params` 0101b358 is read by `sub_0100f22e(…, param)` = `record[param]`. `tbl_od_words` 0101b370 indexed by `$010100ee`.
* `ops_od` 0101b376 (5.5); `od_retry_max` 0101b38e = 2; `tbl_od_actions` 0101b392 = "retry", "restore", "re-spin", "failed" (`$0100fd1e`, printed with "read"/"write").
* `od_cmd_template` 0101b3a2: `35 00 00 33 44 35 33` copied to `$10..$16` of the command block at `$0100f134`; byte `0101b3ad` (0x26) goes to `$d`, `$e` = 1.
* `tbl_od_bytes` 0101b3b2: `00 04 05 00 03 00 00 00 05 00`, `$4282 = table[$4278]` at `$0100f686`.

The optical drive does not exist on the NeXTstation Turbo Color; these matter only for identification.

### 6.2 Version numbers
"NeXT ROM Monitor %d.%d (v%d)" is printed by `sub_01009a2c` (v74 `$01009a58`, v66 `$01008432`)
as `printf(fmt, mg+$312, mg+$30a, mg+$30c)` (v74 pushes the immediates 3, 3, 0x4A when

| | v74 `$01000f5c` | v66 `$01000c4e` |

* cache (NCC / Nitro): "Secondary Cache ram Test Fail", "Secondary Tag ram Test Fail", "\nCache RAM selftest failure\n", "Memory error at location: 0x%x", "Value at time of failure: 0x%x", "Expected: 0x%x     Received: 0x%x", "\nCache tag selftest failure.\n";
* parity memory: "\nparity error: status 0x%x, address 0x%x, data 0x%x\n";
* banner split into three strings: "%d MHz, memory %d nS\n", "Backplane slot #%d\n", "Ethernet address: %x:%x:%x:%x:%x:%x\n" (one string in v66);
* exceptions: "Exception #%d (0x%x) at pc 0x%x sp 0x%x\n", "faultaddr 0x%x\n" (v66: "Exception #%d (0x%x) at 0x%x\n");

* DMA: "dma_start: bad DMA buffer alignment"; floppy: "Sony MPX-111N" (drive record); "cspd" (SCR1 descriptor field), and the new interrupt/SCR bit-descriptor set.
* no ADB or colour/RAMDAC strings exist — those subsystems print nothing.

### 6.4 Strings only in v66
"boot extended diagnostics" (the BOOT_POT parameter, dropped), the un-"of" SIMM names
("16MB nibble mode" .. "1MB parity page mode (illegal)"), the combined banner string,
"Exception #%d (0x%x) at 0x%x\n", "SCSI unaligned DMA segment", "SCSI unaligned DMA",
"dma_list: bad alignment".

### 6.5 Tables
* v66 has a single system-register table (`010105b0`) with the old bit descriptors; v74 keeps it as `tbl_sysreg_old` and adds `tbl_sysreg_new` (selected by `mg+$194`).
* v66 parameter table (`01010614`) = v74 `tbl_params` plus "boot extended diagnostics" (0x20) after "verbose test mode"; handlers at v66 `01002058/010020f2/01002220/01002190`.
* The memory-timing table, help text, images, sine table, fonts and keymaps are byte-identical (see the alignment runs `01014af8-01014cd8`, `01014cd8-01015030`, `01015496-0101a354` (20 KB), `0101a978-0101b07c`).

### 6.6 Code alignment

< 256 bytes, runs >= 384 bytes) cover 55 KB of v74's 109 KB; since absolute
