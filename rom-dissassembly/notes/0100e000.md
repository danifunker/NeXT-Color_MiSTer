# $0100E000 .. $0100FFFF: SCSI driver tail, SCSI disk boot, disk-label / boot-block loader, Canon OMD-1 optical-disk driver

Listing lines ~23439..26587 of `Rev_3.3_v74.asm`. Everything here is plain C code compiled with the
usual `link a6` prologue; arguments are at `$8(a6)`, `$c(a6)`, ... All routines are machine-independent
C except where noted (the only machine-type tests are `mg+$194 == $139` in the DMA code, `mg+$3a8`
in `od_open` and SCR1 cpu-speed bits in `od_ctrl_init`).

## 1. SCSI bus-phase handlers (tail of `sub_0100df9e`, phase table `$01012a5c`)

`sub_0100df9e(sc)` (starts before this range) writes ESP command `$01` (Flush FIFO) to `$02114003`,
then dispatches on `sc+$20d & 7` through the table at `$01012a5c`:
0 = `sub_0100dfe4` DATA OUT, 1 = `scsi_phase_datain`, 2 = "SCSI command phase" (error), 3 = `scsi_phase_status`,
4/5 = error, 6 = `scsi_phase_msgout_err`, 7 = `scsi_phase_msgin`. a2 = `$02114000` (ESP), a3 = sc, a1 = sd.

ESP registers (a2 base `$02114000`, Turbo mirror of `$02014000`): +0 TCL, +1 TCH, +2 FIFO, +3 Command,
+$20 = `$02114020` ESP_DMA_CTRL (bits per Previous esp.h: $80/$40 clock, $20 enable int, $10 DMA mode,
$08 DMA read (scsi->mem), $04 flush, $02 reset, $01 chip type).

* **DATA OUT (`sub_0100dfe4`, $0100dfe4..$0100e05c)**: requires sd+2 == 0 else abort "SCSI bad i/o direction".
  If sc+$218 == 0: state 6, TCL=0, TCH=1, Command=0 then `$98` (DMA Transfer Pad, 256 bytes).
  Else state 4, `dma_setup_chain(sc, sc+$f4, sc+$214, sc+$218, 0)`, `dma_start(sc, sc+$f4, 0)`,
  TCL = sc+$21b, TCH = len>>8, Command = 0 then `$90` (DMA Transfer Information), ESP_DMA_CTRL = `$30`
  (DMA mode + enable int, mem->scsi).
* **DATA IN `scsi_phase_datain` $0100e05e**: requires sd+2 != 0. Empty: state 6, count 256, Command 0 then `$98`.
  Else state 4, chain with dir `$40000`, TCL/TCH, Command 0 then `$90`, ESP_DMA_CTRL = `$38` (DMA, int, scsi->mem).
* **STATUS `$0100e0e6`**: state 3, Command `$11` (Initiator Command Complete: reads status + msg byte).
* **MSG IN `$0100e0f4`**: state 7, Command 0 then `$10` (Transfer Information, PIO).
* **MSG OUT `$0100e106`**: abort with "SCSI msgout phase".
* `loc_0100e10c`: `scsi_abort(sc, msg)`.

### `scsi_msgin_done` $0100e11e (sc) — called from `$0100df44`
sc+$210 must be set ("scmsgin: no current sd"), message byte sc+$21c must be 0 = COMMAND COMPLETE
("SCSI unexpected msg:%d" / "Unexpected msg"), sc+$20f bit 3 must be set ("scmsgin: no FUNCCMPLT").
Then state 5 and ESP Command `$12` (Message Accepted). Errors go to `scsi_abort`.

### `scsi_abort` $0100e188 (sc, msg) — 6 callers
Prints "sc: %s\n". If state == 4 (DMA data phase): **ESP_DMA_CTRL (`$02114020`) = `$20`** (interrupt enable,
PIO, i.e. DMA off) and `dma_stop(sc)`. State = 0; if a current sd exists and its state (+$1d) is 0, set 3
(disconnected); sc+$210 = 0. Finally `sub_0100d9b4(0, 0)` = full ESP re-initialisation (chip reset).

## 2. SCSI disk device ops (`$0101b1b4`)

### `sd_open` $0100e1ec (mg, bd) — devops[0]
1. sd = alloc($70) -> mg+$17e; `sub_0100d9b4(mg, bd)` (ESP reset/config, previous range).
2. unit/lun = bd+4/bd+8 if bd+0 == 1 else 0/0.
3. Up to 10 times: target = `sd_find_target(mg, bd, unit, lun)`; `sub_0100a1a8` (keyboard poll/abort check)
   between tries; stop early if sd state == 5 (bus hung). On failure prints "SCSI Bus Hung\n" or
   "no SCSI disk\n", calls `sd_close` and returns 1.
4. Prints "booting SCSI target %d, lun %d\n", sd+0 = target, sd+1 = lun, `sd_start_unit_wait_ready`,
   `sd_read_capacity` -> if NULL or block length 0: "dev blk len?\n", return 1.
   Else bd+$14 = block length (buf+4), bd+$18 = last LBA (buf+0); return 0.

### `sd_find_target` $0100e2f8 (mg, bd, unit, lun)
For target 0..6: `sd_inquiry(mg, bd, target, lun)`; count responders (d3 from -1); return target when count == unit.
Abort with -1 if sd state == 5. (Targets 0..6 only; 7 is the host.)

### `sd_inquiry` $0100e356
CDB (6 bytes, zeroed): `12 lun<<5 00 00 42 00`; sd+$10 = data buf, sd+$14 = $42, sd+2 = 1. Up to 3 tries of
`sd_command`; success if peripheral device type byte (buf[0]) is 0 (disk), 4 (WORM), 5 (CD-ROM), 7 (optical)
or 8 (changer). Stops retrying if state 5.

### `sd_read_capacity` $0100e40a
CDB (10 bytes): `25 lun<<5 00..00`; 8 bytes into data buf; up to 3 tries; returns buffer address (big-endian
last LBA at +0, block length at +4) or 0 after `sd_print_error(..., "READ CAPACITY")`.

### `sd_request_sense` $0100e49a
CDB `03 lun<<5 00 00 0e 00`, 14 bytes to data buf, issued directly with `sub_0100db8e`; on state 2 with status 8
(BUSY) waits 1 s (`sub_01008936(1000000)` = microsecond delay). 3 tries, then `sd_print_error("REQ SENSE")`.

### `sd_start_unit_wait_ready` $0100e548
CDB `1b lun<<5|1(Immed) 00 00 01(Start) 00`, no data, up to 3 tries. Then TEST UNIT READY (CDB all zero, lun
in byte 1) in a loop: first failure prints "waiting for drive to come ready", each further failure prints "."
and waits 1 s; on success after waiting prints "\n". `sub_0100a1a8` is polled each iteration (user abort).

### `sd_read` $0100e646 (mg, bd, blkno, addr, len) — devops[2]
blocks = ceil(len/blksize); if blocks*blksize != len: "bad dev blk size %d\n", return -1.
CDB READ(6): `08 (lun<<5)|(lba>>16&$1f) lba>>8 lba nblocks(256->0) 00`; sd+$14 = len, sd+$10 = addr, dir in.
Up to 3 `sd_command` tries; returns len - residual (sd+$18). Else `sd_print_error("READ")`, -1.
(READ(6): LBA limited to 21 bits = 2 M blocks, i.e. 1 GB with 512-byte blocks.)

### `sd_write_stub` $0100e726, `sd_label_blkno` $0100e72e
`sd_label_blkno(mg, bd, size, i)` = `ceil(size / bd->blksize) * i` — the four label copies are consecutive
label-sized areas from block 0.

### `sd_command` $0100e750 (mg, bd, sd)
`sub_0100db8e(mg, bd, sd)` returns 1 on success -> return 1. Otherwise on sd+$1d: 2 (complete): status 2
(CHECK CONDITION) -> `sd_request_sense`; status 8 (BUSY) -> 1 s delay; other -> ok(0). 1, 3, 4, 5 -> 0.
Anything else "sdcmd bad state: %d\n". Returns 0 (caller retries).

### `sd_print_error` $0100e7ee (mg, bd, sd, name)
"%s: " then by state: 1 "Selection timeout on target\n"; 2: status 2 -> "Failed, sense key: 0x%x\n" (low nibble of
sense byte 2), 8 -> "Target busy\n", else "sdcmd bad state: %d"; 3 "Target disconnected\n"; 4 "Driver refused
command\n"; else "sdfail bad state: %d\n".

## 3. Generic DMA helpers (used by SCSI, optical and Ethernet code: callers at `$0100fb44`, `$01011772`, `$01011ab2`)

DMA channel registers (Previous dma.c): CSR at `sc+$1c`; the same channel's Next/Limit/Start/Stop are at
CSR+$4000/+$4004/+$4008/+$400c (SCSI: `$02004010..1c`, MO: `$02004050..5c`). CSR write bits: $10000 SETENABLE,
$20000 SETSUPDATE, $40000 DEV2M, $80000 CLRCOMPLETE, $100000 RESET, $200000 INITBUF (old chip) / SETCOMPLETE
(Turbo), $400000 FLUSH (Turbo), $800000 BUFRESET (Turbo). Read bits: $1000000 ENABLE, $2000000 SUPDATE,
$8000000 COMPLETE, $10000000 BUSEXC.

### `dma_init` $0100e8cc (sc)
* sc+$2c &= $8fff; **CSR = $00100000 (DMA_RESET)**; sc+$38 = (sc+$4f)&~15.
* Bounce buffer: i = highest of 3..0 with mg_simm[i] != 0; a = (mg_region[i].last + 15)&~15 - $10000;
  round a up to the next $2000 boundary (if not already aligned) -> sc+$e4. So the DMA bounce area is the
  page-aligned address 64 KB below the top of the highest populated bank.

### `dma_setup_chain` $0100e94a (sc, chain, addr, len, dir)
sc+$e0 = addr, sc+$e8 = len. If dir == 0 (to device): `bcopy(addr, bounce, len)`.
chain[0] = {next 0, start bounce, limit bounce+len, 0, 0}; sc+$34 = 0.
* dir == $40000 (from device): if len > 127: sc+$30 = limit&~15 (aligned tail start), sc+$34 = tail length,
  chain[0].limit = aligned; chain[0].next = chain+$1c; chain[1] = {0, scratch sc+$38, scratch+$20, 0, 0} (the
  last partial 16-byte burst lands in the scratch buffer and is copied back by `dma_cleanup`).
  If len <= 127: sc+$34 = len, sc+$30 = bounce, chain[0] = {0, scratch, scratch + (len+15)&~15} (whole transfer via scratch).
* dir == 0: chain[0].limit rounded up to 16; chain[0].next = chain+$1c; chain[1] = {0, scratch, scratch+$30}.
Every chain therefore has an aligned limit, so the channel can always be started with next/limit + start/stop.

### `dma_start` $0100eacc (sc, chain, dir)
Panics ("dma_start: bad DMA buffer alignment", `sub_01007b38`) if any descriptor start is not 16-byte aligned.
sc+$20 = dir. **Write order on the channel:**
1. CSR = dir | $100000 (RESET) | ($800000 BUFRESET, or $200000 INITBUF when mg+$194 == $139 i.e. machine types 0/1)
2. CSR+$4000 (Next) = chain[0].start; CSR+$4004 (Limit) = chain[0].limit; sc+8 = chain
3. if chain[0].next: CSR+$4008 (Start) = chain[1].start, CSR+$400c (Stop) = chain[1].limit;
   CSR = dir | $30000 (SETENABLE|SETSUPDATE); sc+$2c |= $2000
   else CSR = dir | $10000 (SETENABLE)
4. sc+$2c |= $1000.
Turbo Color path: BUFRESET ($800000) variant.

### `dma_stop` $0100eb90 (sc)
sc+$24 = CSR & $1b000000; CSR = $100000 (RESET); sc+$28 = CSR+$4000 (Next, i.e. where the transfer stopped);
sc+$2c &= $8fff.

### `dma_cleanup` $0100ea5a (sc, resid)
`dma_stop`; resid < 0 -> panic "dma_cleanup: negative resid"; if resid < sc+$34: copy (tail - resid) bytes from
scratch (sc+$38) to sc+$30; if sc+$20 == $40000: `bcopy(bounce sc+$e4, sc+$e0, sc+$e8)` back to the caller.

## 4. Disk boot: label and boot-block loading (fs ops `$0101b1cc`, used for sd and od)

### `boot_fs_open` $0100ebc4 (mg, bd, a3, a4, a5) — fsops[0]
Allocates $3930, rounds up to an 8 KB boundary -> mg+$182. Calls devops[0] open(mg, bd, a3, a4, a5).
On success: labelbuf+$1c4c = -1, +$1c50 = +$1c54 = 0, labelbuf+0 = 16-aligned pointer into an $2010-byte
allocation (sector cache). Returns open's result (0 ok).

### `boot_fs_load` $0100ec4e (mg, bd, &namep) — fsops[2]
* Command-line handling: if `*namep` starts with '-' keep it, else advance to the first space or NUL (skip the
  device/file part; what remains are the boot flags) and store back.
* `boot_read_label(mg, bd)` == 0 -> "Bad label\n", return 0.
* **Mis-decoded region `$0100ec9a..$0100ed1b`** (descent treated it as string `str_0100ec9a`; it is code, the
  `bne.b str_0100ec9a` at `$0100ec8e` jumps into it). Decoded:
  * a2 = label (labelbuf+4). If `*(mg+$fc)` (boot file name) is empty: if label+$84 (cd_kernel) is empty
    -> "No bootfile in label\n", return 0; else mg+$fc = &label->cd_kernel.
  * fs sector size = label+$5c; must be >= bd blksize and a multiple of it, else
    "dev blk len %d, fs sect %d\n", return 0.
  * for i in 0..1: off = label->cd_boot_blkno[i] (+$7c+4i) * secsize; if off < 0 skip;
    `boot_exec_blk0(mg, bd, off)`; non-zero result is returned (the boot program returned a value).
  * "Can't load blk0 boot\n", return 0.

### `boot_read_label` $0100ed2e (mg, bd)
for i in 0..3: blk = devops[4](mg, bd, $1c48, i); `boot_fs_seek(mg, bd, blk * bd->blksize)`; bzero(label, $1c48);
`boot_fs_read(mg, bd, label, $1c48)` must return $1c48; `boot_check_label(label, blk)` -> 1 = ok. Returns 0 if none.
So 4 label copies are tried; for sd at blocks 0, 15, 30, 45 (512-byte blocks: ceil($1c48/512) = 15);
for od at sectors 0 and $3c460 (copies 2/3 = -1 -> seek to a negative offset; the read then fails harmlessly).

### `boot_check_label` $0100edc4 (label, blkno)
version == 'NeXT' ($4e655854) or 'dlV2' ($646c5632): len $1c48, checksum word at +$1c46;
'dlV3' ($646c5633): len $230, checksum at +$22e; else "Bad version 0x%x\n". label+4 must equal blkno
("Bad blkno\n"). Checksum: word zeroed, `sub_0100743c(label, len)` (16-bit checksum routine from an earlier
range) compared to stored ("Bad cksum\n"), then restored. Returns 1 ok / 0 bad.

### `boot_exec_blk0` $0100ee54 (mg, bd, byteoff) — the boot-block sequence
1. `boot_fs_seek(byteoff)`; read $400 bytes into a stack buffer (a6-$400); must return $400 else "short read\n".
2. `sub_01006914(buf, &nread, &entry, &loadaddr)` parses the header: a.out OMAGIC (`0x107` at +2: text+data
   size from +4/+8, entry from +$14, header 32 bytes skipped) or Mach-O (`feedface`, filetype 5 MH_PRELOAD,
   first LC_SEGMENT: vmaddr -> entry and load address, fileoff/filesize). It copies the part of the image already
   in the 1 KB buffer to loadaddr and returns the number of bytes still to read (0 -> fail, "unknown binary format").
3. Reads the remaining bytes to loadaddr (`boot_fs_read`), must match else "short read\n".
4. Builds the boot argument string in labelbuf+$1c58 with `sub_0100778a` (sprintf): if bd+0 == 1:
   "%s(%d,%d,%d)%s" (mg+$f0 device name, bd+4, bd+8, bd+$c, mg+$fc file name) else "%s()%s".
5. `jsr entry` with the string pointer as the single argument; the return value is returned.
Nothing in the ROM checks a magic number in the boot block itself beyond the a.out/Mach-O header.

### `boot_fs_seek` $0100ef50, `boot_fs_read` $0100ef66, `boot_fs_close` $0100f044
`boot_fs_read(mg, bd, dst, len)`: loop: blk = pos / blksize; chunk = min($2000, remaining) rounded up to a blksize
multiple; if blk is not the cached block (labelbuf+$1c4c/+$1c54) call devops[2](mg, bd, blk, cache, chunk) which
must return chunk (else return -1), then labelbuf+$1c4c = blk, +$1c54 = chunk. The cache is reused (no refill)
when blk >= cached block and blk*blksize+chunk <= cached end. Copy starts at `cache + (pos % blksize)`
(remainder of `divu.l` at `$0100f014`; only correct when blk == cached block, which is always the case for the
ROM's access pattern) and runs until len is exhausted or the end of the 8 KB cache, advancing labelbuf+$1c50.
Returns len.

## 5. Canon OMD-1 optical disk driver

### Register map assumed (base passed by `od_open` = `$02112000`, Turbo mirror of `$02012000`; od+$20c holds it)

Names from Previous `mo.c` (OSP = optical storage processor / formatter). All byte-wide.

| off | reg | ROM use |
|---|---|---|
| +0 | track number high | written before a transfer (`od_cmd_xfer`), read back on timeout |
| +1 | track number low | |
| +2 | sector number (3:0) / increment (7:4) | written `sector | $10` (increment 1) |
| +3 | sector count | |
| +4 | interrupt status (r), write 1s clear | bit 0 CMD_COMPL polled; written `$fc` to clear all; bits: 1 ATTN, 2 OPER_COMPL, 3 ECC_DONE, 4 TIMEOUT, 5 READ_FAULT, 6 PARITY_ERR, 7 DATA_ERR |
| +5 | interrupt mask | written 0 at init; **read** in `od_issue` (waits for bit 2) - odd, see note |
| +6 | controller CSR2 | `odv+$20f7 | $80` (SECT_TIMER + drive select) before each drive command / transfer |
| +7 | controller CSR1 = formatter command | 0 reset, `$20` FMT_RD_STAT, `$02` READ, `$01` WRITE, `$04` ERASE, `$80/$40` ECC read/write |
| +8 | CSR_H (drive command high byte) | |
| +9 | CSR_L (drive command low byte; write fires the command) | |
| +$a | error status | bit 0 ECC, 1 CMP, 2 TIMING, 3 STARVE |
| +$b | ECC count | not used here |
| +$c | init | `$c3` (SEC_GREATER|ECC_STV_DIS|ID_1234) or `$d3` (+25_MHZ) when SCR1 cpu speed bits 2:0 >= 2 (25/33 MHz: Turbo) |
| +$d | format | `$26` (from table `$0101b3ad`): read gate 6, write gate $20 |
| +$e | mark | 1 |
| +$10..+$16 | flag0..6 | `35 00 00 33 44 35 33` (table `$0101b3a2`) |

Drive command words (Previous mo.c): `$0000|trk` seek, `$a000|hi` high-order seek, `$1000` recalibrate, `$2000`
return drive status, `$2800` extended status, `$2a00` hardware status, `$4100` select read head, `$5000` reset
attn/status, `$5300` start motor, `$5600` eject, `$5900` spiral on. Drive status bits: `$4000` DS_EMPTY (no
disk), `$0200` DS_STOPPED, `$0400` DS_SIDE (upside down), `$0004` DS_INSERT etc.

DMA: channel CSR `$02000050` (od+$1c), Next/Limit/Start/Stop at `$02004050..5c`, through the generic helpers
above. NOTE: Previous's Turbo I/O table has neither the OSP registers at `$0201x2000` (only 4 "GPIO" bytes)
nor a `$02000050` DMA channel, i.e. on a Turbo the probe in `od_ctrl_init` just times out. For the FPGA core the
optical driver is only reached when the user explicitly boots from "od"; the probe reads `$02112004` bit 0 for
3,000,000 iterations, so that address must read as 0 (or bus-error) on the core.

### od softc (mg+$18a, $428a bytes; DMA header identical to sc)
+0 chain ptr (= od+$f4), +$1c DMA CSR ptr, +$20c OSP register base, +$210 current DMA address,
+$21c 32-bit **software** flag word (not a hardware register), +$4250 track (word), +$4252 seek target track,
+$4254 current logical sector, +$425c physical sector, +$4260 sectors remaining (word), +$4262 sectors this chunk,
+$4263 sector count byte, +$4264 op (2 read, 1 write, 4 erase), +$4265 requested head/op, +$4266/+$4268/+$426a

### `od_cmd_dispatch` $0100f3e0 (od, odv, cmd, iob)

3/4/9/10/11 `od_cmd_xfer`, 5 `od_cmd_next_chunk`, 6 `od_cmd_error_finish`, 7 `od_cmd_after_eject`,
8 `od_cmd_resume`, 12 `od_cmd_fail_ret`, 13 `od_cmd_check_motor`, 14 `od_cmd_finish`. Registers: a3 = od,
a5 = odv, d3 = od+$20c (regs), d4 = iob, a4 = geometry.

* **`od_cmd_start` (1)**: od+$4283 = 1 (retry cmd). Chunk = min(remaining, $40000/secsize = 256 sectors).
  If bit 19 clear: translate logical sector through the alternate-group geometry (+$76 ag size, +$78 alts,
  +$7a offset, +$70 front) to a physical sector, limiting the chunk to the end of the group; else physical =
  logical. Add odv+$20f8 (first logical sector offset); track = phys / 16 -> od+$4250, sector = phys % 16 ->
  od+$4280. od+$4278 = od+$4265 (1 -> 4). Then on od+$4278: `2` (read): od+$427e = `$4100` (select read head)
  -> if odv bit 12 (spiral on) clear: send `$5900` spiral-on (od+$4274, bit 30, `od_issue`), next cmd =
  od+$4281, set odv bit 12, go to `od_cmd_xfer` tail; else seek: clear bit 13, `od_drive_cmd($a000 |
  (track-1)>>12, 9)` high-order seek, then (**mis-decoded `$0100f644..$0100f66b`**, decoded: od+$4252 = track-1,
  od+$4274 = od+$427e, set bit 30, clear bit 29, next cmd 2). `$f0`: `od_drive_query($2000)` drive status; DS_EMPTY
  (bit 14) -> error $14 + bit 14; else od+$4274 = `$5000` reset-attn, bit 30, `od_issue`, cmd $d. `$f1`: status
  twice ($2000, $5000) then od+$4274 = `$5600` eject, cmd 7. Other op -> error $b.
* **`od_cmd_seek_low` (2)**: od+$4274 = od+$4252 & $fff (DRV_SEK), bits 30|29 set (drive cmd + formatter cmd
  pending), next cmd = `$0101b3b2[od+$4278]` = {0,4,5,0,3,0,0,0,5} (read -> 5), then `od_cmd_xfer`.
* **`od_cmd_xfer` (3/4/9/10/11, `loc_0100f796`)**: +0 = track>>8, +1 = track, +2 = sector | $10, +3 = count byte
  (od+$4263); `od_issue(od, odv)`; `od_complete(od, odv, iob)`.
* **`od_cmd_next_chunk` (5)**: remaining -= chunk; if > 0: od+$210 += chunk*secsize, od+$4254 += chunk, dispatch cmd 1;
  else iob |= 2 (done).
* **`od_cmd_error_finish` (6)**: `od_print_error(od, 3)`, iob+$1c = error code, iob |= 6.
* **`od_cmd_after_eject` (7)**: odv+$2104 &= $3fff, clear bit 23; if bit 12: clear it and error finish; else cmd 5 path.
* **`od_cmd_resume` (8)**: clear bit 23, dispatch od+$4285.
* **`od_cmd_check_motor` (13)**: `od_drive_query($2000)`; DS_STOPPED (bit 9) -> `od_drive_cmd($5300, 9)` start
  motor, cmd $e, `od_complete`, return 1; else **`od_cmd_finish` (14)**: if bit 24: clear bits 24 and 17, iob |= 2.

### `od_issue` $0100fadc (od, odv)
* If bit 29 and (od+$4278 & $c3): bit 20 set; dir = (od+$4278 & $82) ? $40000 : 0; len = chunk * secsize;

### `od_drive_cmd` $0100fc00 (od, odv, cmd16, flags)

## 6. Descent problems to fix in the generator

Code mis-decoded as data (all are the fall-through/branch targets shown):
* `$0100ec9a..$0100ed1b` (`str_0100ec9a`, target of `bne.b` at `$0100ec8e`) — body of `boot_fs_load`.
* `$0100f3ba..$0100f3df` (`str_0100f3bd`) — tail of `od_start_io`.
* `$0100f644..$0100f66b` (`str_0100f644`) — inside `od_cmd_start`, falls through from `$0100f63e`.
* `$0100f9c6..$0100fa0d` (`str_0100f9c6`) — inside `od_complete`.
* `$0100fdf0..$0100ff69` (`str_0100fdf0`, `str_0100fdff`, `str_0100fe0b`, `str_0100fee4`) — body of
  `od_read_drive_status` `$0100fdc6` (its real size is $1a4 bytes, not 42).
In each case the descent stopped because a `bsr`/`bne` target was skipped after the string scanner claimed the
bytes; a 4+ printable-byte run inside code (`Bj`, `Hx` = `clr.w`, `pea`) fooled `looks_text`. Also
`sub_0100ff6a` is listed with `sub_01010002` as its `rts` (the `rts` at `$01010002` belongs to `od_drive_query`;
`sub_01010002` is not a routine), and `sub_01010008`/`sub_0101000c` are mid-prologue labels of `sub_01010004`.
The disassembler prints `divu.l <ea>,d0:d1` forms as `divu.l $14(a4),d1`, hiding the remainder register
(e.g. `$0100eccc`); harmless but worth noting when reading `tst.l d0` after a divide.

## 8. Uncertainties
* od+$21c bit meanings are inferred from use only; names above are descriptive, not NeXT's.
* The wait on `+5 & 4` in `od_issue` (write path) contradicts Previous, where +5 is the write-only interrupt mask;
  the ROM may treat +5 as a readable status on real hardware. Not on the boot (read) path.
* The alternate-group geometry arithmetic in `od_cmd_start` ($0100f466..$0100f4c0) was not verified in detail.
* `sub_0100743c` is assumed to be the 16-bit label checksum (called with (buf, len) and its result compared to
  the stored word); it lives in another range.
* Bootfile selection when `mg+$fc` is non-empty: the string is used as given (the sd/od path itself never opens
  a file; the blk0 boot program does), so "No bootfile in label" only matters when nothing was typed.
