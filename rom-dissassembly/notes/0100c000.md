# ROM range $0100C000 .. $0100DFFF (listing lines ~20201 .. 23439)

Three subsystems live here:

1. the tail of the video-driver setup plus two methods of the third "video driver" vector
   (brightness / video enable),
2. the complete TMC ADB driver (bus reset, talk/listen, keyboard and mouse probing, keyboard
   event translation, magic keys),
3. the first half of the SCSI driver (NCR 53C90 "ESP" init, command start, interrupt service,
   phase dispatch; the DATA IN / STATUS / MSG IN phase cases and the message-in handler
   continue in the next range at `sub_0100e05e..sub_0100e11e`).

Conventions used below: `mg` = monitor globals struct (`sub_01000686` returns it as
`vbr+4`). `sub_01008936(n)` is the microsecond delay loop (event counter based),
`sub_01007dd6(size)` is the monitor allocator (`mg_alloc_brk -= size`, returns pointer),
`sub_01007772` is printf, `sub_0100a1a8` is the console poll (checks abort / power key).

## Established facts that apply to the whole range

* `mg+$194 == $139` means **non-Turbo** machine. It is set at `$01000d32`/`$01000d3c` for
  machine types 0..3 only. Every `cmpi.l #$139,$194(aN)` in this range therefore selects the
  non-Turbo code path; Turbo Color (type 5) always takes the `bne` side. (The brief listed this
  field as "unknown"; it is effectively `mg_is_nonturbo`, possibly a NetBSD-style
  `mg_machine_class` value.)
* `mg+$34c` = console slot (byte), `mg+$34d` = video driver index (byte), written at
  `$0100c132`/`$0100c138` by the routine that ends at `$0100c144` (starts before this range).
  The video driver vector table is at `$0101b080`: 3 vectors x 7 methods x 4 bytes
  (`sub_0100b7c0` probes with method 0, `$0100b84e` calls method 3 = "enable",
  `$0100b896` calls method 1). Vector 2 (`$0101b0b8`) = `bf72, bf9e, c146, c14e, c1aa, c1aa, c18a`;
  this is the vector that contains the routines in this range.
* Video geometry computed at `$0100c012..$0100c12e` (routine starts in the previous range, ends
  here): frame buffer base `mg+$368`/`$364` = `$0B000000` on non-Turbo, `$0C000000` on Turbo;
  bytes per row = `(0x480 or 0x460) >> 2` (1152 px non-Turbo, 1120 px Turbo, 2 bpp),
  `mg+$36c` = rowbytes*832, `mg+$374`/`$370` = base + rowbytes*832 (end of visible screen),
  `mg+$378` = rowbytes * ((0x38e or 0x3a8) - 0x340) ... (extra rows below the visible area:
  0x38e=910 / 0x3a8=936 total rows). All are mono-geometry values even on the colour machine;
  the colour driver is elsewhere.

## Video driver vector 2 methods

### sub_0100c146 `vid2_nop_m2` (8 bytes, table `$0101b0c0`)
Empty method (`link/unlk/rts`).

### sub_0100c14e `vid2_enable` (60 bytes, table `$0101b0c4`, called from `$0100b84e` with (mg))
* `d0 = bfextu $17(mg){4:6}` = NVRAM word bits 19:14 = `ni_brightness` (6 bits; rtcnvram.c
  struct: `ni_reset:4, ni_alt_cons:1, ni_allow_eject:1, ni_vol_r:6, ni_brightness:6, ...`).
* `d1 = brightness_lfsr_tab[d0] | $40` (table at `$0101b0d4`, 64 bytes), written as a **byte** to
  `$02110000` (brightness register, Turbo mirror of `$02010000`).
* Turbo only (`mg+$194 != $139`): `move.l #$04000000, $02200080` = TMC video interrupt register
  byte 0 = `$04` = `TMC_VI_ENABLE` (video output on, interrupt disabled, no pending). The
  exception dispatcher writes `$05000000` (enable + intr bit) at `$01001a36`.

**Brightness register encoding (important for the FPGA):** the 64-entry table is not monotonic:
`00 01 03 07 0F 1F 3E 3D 3B 37 2F 1E 3C 39 33 27 0E 1D 3A 35 2B 16 2C 18 30 21 02 05 0B 17 2E 1C
38 31 23 06 0D 1B 36 2D 1A 34 29 12 24 08 11 22 04 09 13 26 0C 19 32 25 0A 15 2A 14 28 10 00 00`.
It is the state sequence of a 6-bit LFSR: `next = ((v << 1) | !(bit5 ^ bit4)) & $3F`, so entry n
is the LFSR state after n steps from 0 (63 distinct states, entries 62/63 wrap to 0). The
brightness hardware therefore expects a 6-bit LFSR-coded level in bits 5:0 of `$02110000`
with bit 6 always set. Level 0 = dimmest (`$40`), 61 = `$50`.

### sub_0100c18a `vid2_set_brightness` (32 bytes, table `$0101b0d0`)
Args `(mg, level)` (`$c(a6)` = level 0..63). `$02110000 = brightness_lfsr_tab[level] | $40`.
No machine-type test.

### sub_0100c1aa `vid_nop` (8 bytes; tables `$0101b090, b0ac, b0c8, b0cc`)
Empty method shared by all three vectors.

## ADB driver (Turbo Memory Controller ADB window `$02208000`)

Register offsets (adb.c lines 197-206): INTSTATUS +00, INTMASK +08, SETINT +10, CONFIG +18,
CTRL +20, STATUS +28, CMD +30, COUNT +38, DATA0 +80, DATA1 +88. All accesses are 32-bit
`move.l`; only the low byte carries the bits given in adb.c (INT: REJECT 1, POLLSTOP 2, ACCESS 4,
RESET 8; CTRL: EN_POLL 1, DIS_POLL 2, XMIT_CMD 4, RESET_ADB 8, RESET_WD $10; STATUS: CONFLICT 1,
REQUEST 2, TIMEOUT 4, DATAPEND 8, RESET $10, ACCESS $20, POLL_EN $40, POLL_OV $80; CONFIG:
SYSTEM 1, WATCHDOG 2; CMD: reg bits 1:0, cmd bits 3:2 (0 reset, 1 flush, 2 listen, 3 talk),
addr bits 7:4; COUNT = bit count, bits 6:0).

Observed protocol conventions:
* **Interrupt acknowledge** is `move.l (INTSTATUS),(INTSTATUS)` (read, write the same value back)
  or writing the single bit (`8` after a reset, `4` after an access): write-1-to-clear.
* The ROM **never enables INTMASK** (`adb_init` clears it) and never writes SETINT. Everything is
  polled on INTSTATUS. The ADB IRQ path (`adb_intr`) exists but is unreferenced.
* After every poll the ROM writes `CTRL = $10` (RESET_WD) - it kicks the ADB watchdog.
* `COUNT` is written as `bytes * 8` and read back as `COUNT >> 3` (bit count).
* Data is packed big-endian into DATA0 (bytes 0-3) and DATA1 (bytes 4-7); DATA1 is only touched
  when the length is > 4.

| `mg+$3be` | long: set to 2 by `adb_probe_kbd_alt_video`; also set by the machine-type dispatch (`$01000da2`, `$01000dc8`). Looks like "console keyboard type" (2 = ADB). Uncertain. |

### sub_0100c1b4 `adb_init` (270 bytes, called from `$010017da`, Turbo only: guarded by `mg+$194 != $139`)
1. `CONFIG = 0`, `INTMASK = 0`, `mg+$3de = mg+$3da = 0`.
2. `adb_reset_bus(1)`: ack INTSTATUS, `CTRL = $08` (RESET_ADB), spin until INTSTATUS bit 3 (RESET), write 8 to clear.
3. For addr = 1..7: `adb_talk(addr, 3, buf, &count)`. If count != 0 the device exists:
   `devtab[addr].handler_id = buf[1]`; if addr == 2 `devtab[2].index = 2` (keyboard handler);
   addr 2 -> `adb_kbd_init(2, buf)`; addr 3 -> `adb_mouse_init(3, buf)`; chain the address into the
   previous entry's +6; `mg+$3d2 = addr` unless it is already 3.
4. Closes the chain (last entry +6 = first address), `mg+$3d6 = mg+$3d2`, and if a device exists
   sends `adb_send_cmd(addr<<4 | TALK<<2 | reg 0, NULL, 0, nowait)` - the first poll of register 0.
   Its answer is never collected by an interrupt (see `adb_intr`), it is picked up by
   `adb_kbd_poll` later.

### sub_0100c2c2 `adb_intr` (214 bytes, no reference found)
The intended ADB interrupt service: `INTSTATUS` read + written back (ack), `STATUS` read,
`CTRL = $10`. If INTSTATUS bit 2 (ACCESS): if STATUS bit 3 (DATAPEND): `n = COUNT>>3`, read
DATA0 (and DATA1 if n > 4) into a local 8-byte buffer, call `adb_dev_handler_tab[devtab[cur].index](buf, n)`.
Then next device = `devtab[cur].next` if STATUS bit 1 (REQUEST = service request pending) else
`mg+$3d2`; issue talk reg 0 to it (nowait). If no ACCESS int and STATUS bit 5 (access in
progress) return. Returns 1. **Not referenced anywhere** (no pointer table, no bsr); either dead
code or installed through a mechanism the descent missed. The dispatcher's interrupt path
should be checked for an ADB entry, but the mg interrupt-vector fields seen so far do not
point here.

### sub_0100c398 `adb_kbd_poll` (192 bytes, called from `$0100d018`, `$0100d426`)
Arg: pointer to an 8-byte buffer. Returns 0 if `mg+$3d2 == 0` (no ADB device). Otherwise:
ack INTSTATUS, read STATUS, `CTRL = $10`. If ACCESS int and `mg+$3d6 == 2` and DATAPEND:
copy DATA0 (and DATA1 if count > 4) to the buffer, result = 1. If no ACCESS int and STATUS bit 5
(access in progress) return 0 immediately. Otherwise: `mg+$3d6 = 2`, send talk addr 2 reg 0
(nowait), delay 8000 us, return result. So the keyboard is polled every call with an 8 ms gap.

### sub_0100c458 `adb_reset_bus(wait)`
`INTSTATUS` ack, `CTRL = $08`; if wait: spin on `INTSTATUS & 8`, then `INTSTATUS = 8`.

### sub_0100c482 `adb_send_cmd(cmdword, dataptr, len, wait)` (120 bytes)
The command is passed as a **word** whose high byte is the ADB command byte
(`addr<<4 | cmd<<2 | reg`, built by the callers with `bfins` into bits 15:8 of a long); the
routine reads it as `move.b $a(a6)`. Sequence: `CMD = cmdbyte` (long write), if dataptr:
`DATA0 = data[0..3]`, `DATA1 = data[4..7]` if len > 4, `COUNT = len*8`; else `COUNT = 0`.
`CTRL = $04` (XMIT_CMD). If wait: spin on `INTSTATUS & 4`, then `INTSTATUS = 4`.

### sub_0100c4fa `adb_talk(addr, reg, dataptr, countptr)` (120 bytes; also in tables `$0100c70c`, `$0100d8d6` - those are `lea` operands, not a real pointer table)
Sends TALK (cmd 3) with wait, then if `STATUS & 8` (DATAPEND): `*countptr = COUNT>>3`, copies
DATA0/DATA1 to `dataptr`; else `*countptr = 0`.

### sub_0100c572 `adb_listen(addr, reg, dataptr, len)`
Sends LISTEN (cmd 2) with `dataptr/len`, wait = 1.

### sub_0100c5a6 `adb_kbd_raise_nmi` (called from the three magic-key sites `$0100cbd6`, `$0100cfec`, `$0100d872`)
Turbo only: `adb_reset_bus(1)`, then `$02200020 |= 1` (32-bit RMW; bit 0 of byte 3 = TMC NMI:
Previous `tmc_nmi_write3` -> `set_interrupt(INT_NMI)`), delay 8000 us. This is how Cmd+Alt+`
on an ADB keyboard enters the monitor: the exception dispatcher (`$01001c80`) sees the NMI
register bit set and calls `sub_01009fde`, which clears it (`clr.l $02200020`).

### sub_0100c5e0 `adb_set_config(flag)` (70 bytes, no reference found)
Turbo only: `CTRL = $10`; if flag == 1 and `mg+$3d6 != 0`: `CONFIG = 3` (SYSTEM | WATCHDOG),
else `CONFIG = 0`. Probably meant to hand the bus to the OS / enable the watchdog before boot.

### sub_0100c626 `adb_probe_kbd_alt_video(mg)` (100 bytes, called from `$0100acba` in the init path `sub_0100ac8a`)
`mg+$3be = 2`; `adb_reset_bus(1)`; delay 5000 us; `adb_talk(2, 3, buf, &count)`. If the
keyboard answered (count != 0) **and** SCR2 byte 2 bit 4 is set (`btst #4,$0200d002`; Previous
sysReg.c line 210 initialises this bit to 1 on Turbo with the comment "video mode is 25 MHz"),
and machine type (`mg+$3a8`) is 4..9: jump through `tmc_alt_timing_tab` (`$01012124`, 6 entries):
types 4, 6, 8 (mono) -> `tmc_alt_timing_mono`; types 5, 7, 9 (colour) -> `tmc_alt_timing_color`.
Note the ROM checks the ADB keyboard **before** `adb_init` runs (this is called from the earlier
init routine); it is a presence probe only.

### sub_0100c68a `tmc_alt_timing_color` / sub_0100c6a4 `tmc_alt_timing_mono`
Straight register writes, then jump back to the epilogue of `sub_0100c626` (`loc_0100c6bc`).
Decoded with the tmc.c layout fporch[31:25] sync[24:19] bporch[18:12] display[11:0]:

| register | value | fporch | sync | bporch | display | used for |
|---|---|---|---|---|---|---|
| H `$02200088` | `$29044118` | 20 | 32 | 68 | 280 (=$118) | colour types 5,7,9 (alt) |
| V `$0220008C` | `$021A0340` | 1 | 3 | 32 | 832 | colour types 5,7,9 (alt) |
| H `$02200088` | `$5B02B118` | 45 | 32 | 43 | 280 | mono types 4,6,8 (alt) |
| V `$0220008C` | `$0041C340` | 0 | 8 | 28 | 832 | mono types 4,6,8 (alt) |
| H reset (`$01000380`) | `$165A10D0` | 11 | 11 | 33 | 208 | colour, reset default |
| V reset | `$10412270` | 8 | 8 | 18 | 624 | colour, reset default |
| H reset (`$0100039a`) | `$6302F118` | 49 | 32 | 47 | 280 | mono, reset default |
| V reset | `$00438340` | 0 | 8 | 56 | 832 | mono, reset default |
| tmc.c defaults | | 24 | 32 | 72 | 280 / 8,8,48,832 | Previous |

Observations: both alternate timings keep an 832-line frame and a 280-unit active line
(mono unit = 4 pixels -> 1120 px); the colour alternate timing abandons the colour reset values
(208/624 - apparently a different counter unit) and uses mono-style counts with a shorter total
line (20+32+68+280 = 400 vs 408 for the mono default). Which monitor this targets is **not
proven**; the trigger (ADB keyboard present + SCR2 "25 MHz video mode" bit) suggests the ADB
variants of the Turbo boards, which drive a non-NeXT monitor. For the FPGA these are the only
other timing values the ROM ever writes; if the core never reports an ADB keyboard at address
2 this path is dead. Turbo Color (type 5) would take `tmc_alt_timing_color`.

### sub_0100c6c4 `adb_kbd_init(addr, buf)` (196 bytes, called from `adb_init`)
`mg+$3e2 |= 1`; `buf[1] = 3`; `adb_listen(addr, 3, buf, 2)` (set handler ID 3 = Apple Extended
keyboard protocol); `adb_talk(addr, 3, buf, &n)`; if n == 2 and `buf[1] == 3`: `mg+$3e2 |= 2`;
`adb_talk(addr, 2, buf, &n)` (reg 2 = modifier/LED state); if n >= 2: caps-lock state from
`buf[0]` bit 5 (0 = down) into `mg+$48a` bits 1 and 0; `buf[1]` bit 1 (caps LED) = `buf[0]` bit 5,
`buf[1] |= 5` (num-lock and scroll-lock LEDs off, 1 = off), `adb_listen(addr, 2, buf, 2)`.

### sub_0100d8a6 `adb_mouse_init(addr, buf)` (224 bytes, called from `adb_init`)
`mg+$3e2 |= $10000`; talk reg 3; `buf[1] = 3`; listen reg 3 (2 bytes) (request handler 3);
talk reg 3; if handler is now 3: talk reg 1; if 8 bytes returned: three `adb_listen(addr, 1, buf, 8)`
with `buf[0..1]` = `00 83`, `01 82`, `02 81` (rest of the 8 bytes = the reg 1 data returned by the
talk); then `mg+$3e2 |= $20000`. This is a 3-button (extended mouse protocol) setup; the mouse
data itself is never consumed by the ROM (device-table index stays 0 -> stub handler).

### sub_0100c788 `adb_kbd_handler(data, count)` (464 bytes, entry [2] of `$0101b114`)
The register-0 data handler for the keyboard (only reachable through `adb_intr`, so effectively
unused - the polled path `adb_kbd_getevent` contains the same code inline twice).
1. Each of the two ADB key bytes (`bit 7 = release, bits 6:0 = ADB keycode, $7F = none`) is
   stored into the 2-word ring `mg+$486[write&1]` and `mg+$3de++`.
2. While `mg+$3da != mg+$3de`: take a word, start from the current event `mg+$144`, set the
   key-up bit and the NeXT keycode from `adb_to_next_keycode_tab[adb code]`
   (`$0101b134`, 128 bytes: ADB 0 'a' -> NeXT $39, etc.), set valid ($8000) if the table entry
   is non-zero. Table entries >= $80 (F1..F15, help/home/pgup/pgdn/end at ADB $60..$7A) are
   "virtual command" keys: on press the event gets `$1000|$800` (both cmd bits) and a held-count
   in `mg+$48b` bits 5:1 is incremented; on release the count is decremented and, if it reaches 0
   and no real cmd key is held, the cmd bits are cleared. ADB $6B (F14) toggles `mg+$48b` bit 6
   (scroll lock) and rewrites the LEDs (listen reg 2) on extended keyboards.
3. Modifier keys dispatch through two 72-entry jump tables indexed by `ADB code - $36`:
   release table `$0101213c` and press table `$0101225c` (entries for $36 ctrl, $37 cmd, $38 shift,
   $39 caps lock, $3A option, $72 help, $7B shift_r, $7C option_r, $7D ctrl_r; every other entry
   points at the common exit `loc_0100cb8e`). They update `mg+$48a` and the modifier bits of the
   event (see `names/0100c000.py` for each case).
4. Common exit (`loc_0100cb8e`): if the event is valid, NeXT keycode $25 with byte-2 bits 3 and 5
   set (cmd_l + alt_l, i.e. Cmd+Alt+`*`) -> `sub_01009860` (sends the KMS magic reset word
   `$1000A825`); keycode $26 (backquote) with cmd_l + alt_l on key-down -> `adb_kbd_raise_nmi`.
   Otherwise `andi.b #$df` clears bit 5 (alt_l) of byte 2 and copies (the now cleared) bit 5 into
   bit 3 - net effect: cmd_l and alt_l are stripped from delivered events (looks like a compiler
   ordering artefact; noted, not explained).

### sub_0100d032 `adb_kbd_getevent(evptr)` (354 bytes; called from `$0100a086`, `$0100a20a`, `$0100a298`, `$0100a2f8` with `evptr = &mg+$144`)
The polled keyboard entry point used by the console code. If the ring (`$3da != $3de`) has a
word: process it exactly as `adb_kbd_handler` step 2-4 (code copy C, tables `$010125bc` /
`$0101249c`), store the event to `*evptr`, return 1 (0 if the event was consumed as the NMI magic
key). If the ring is empty: `adb_kbd_poll(buf)`; if it returned data push both key bytes to the
ring (step 1), and if the ring is now non-empty process one word (code copy D, tables
`$010127fc` / `$01012918`), else return 0.

### sub_0100cc06 `adb_kbd_getevent_unused(evptr)` (354 bytes, prologue-seeded)
Byte-for-byte the same logic as `adb_kbd_getevent` (code copy B, tables `$0101237c` /
`$0101249c`) with a slightly different frame layout. **No reference found anywhere** (no bsr,
no pointer table, no split-word occurrence) - dead code left by the compiler/linker.

### sub_0100d986 / sub_0100d98e / sub_0100d9aa
`adb_nop` (empty), `adb_kbd_present` (returns `mg+$3e2 & 1`; unreferenced),
`adb_dev_handler_stub` (empty, entries 0,1,3..7 of `$0101b114`).

## SCSI driver (NCR 53C90 "ESP" at `$02114000`, Turbo mirror of `$02014000`)

ESP register map (ioMemTabTurbo.c lines 176-194): +0 transfer count low, +1 transfer count
high, +2 FIFO, +3 command, +4 status (r) / select bus ID (w), +5 interrupt status (r) / select
timeout (w), +6 sequence step (r) / sync period (w), +7 FIFO flags (r) / sync offset (w),
+8 configuration 1, +9 clock conversion factor, +A test, +B configuration 2.
`$02114020` = SCSI DMA control (esp.h: bits 7:6 clock select (00 = 10 MHz, 01 = 12.5, 11 = 16.6,
10 = 20), $20 ENABLE_INT, $10 MODE_DMA, $08 DMA_READ (scsi->mem), $04 FLUSH, $02 RESET (ESP hard
reset), $01 CHIP_TYPE (1 = WD33C92)).

### Data structures

`softc` (allocated in `scsi_init`, 0x21e bytes, pointer kept in `mg+$186`):

| offset | use |
|---|---|
| +$08 | dma chain head (set by dma_start `sub_0100eacc`) |
| +$1c | pointer to TDMA CSR `$02000010` (the DMA channel; +$4000/+$4004 next/limit, +$4008/+$400c start/stop) |
| +$20 | DMA direction word passed to dma_start (0 = mem->dev, `$40000` = dev->mem) |
| +$24 / +$28 | CSR status (`& $1B000000`) and next pointer read back by dma_stop `sub_0100eb90` |
| +$2c | dma flags: initialised to 6; `sub_0100e8cc`/dma_stop `and $8fff`; dma_start ors `$1000` (`$2000` if chained); bit 14 (`$4000`) tested as "bus error" after a transfer |
| +$30, +$34, +$38 | DMA bounce buffer bookkeeping (`+$38` = `(softc+$4f) & ~$f`, an aligned buffer inside the softc) |
| +$e0/+$e4/+$e8 | extra DMA buffer used for dev->mem transfers (`+$e4` computed in `sub_0100e8cc` from the top of the memory region table) |
| +$f4 | dma descriptor used by the SCSI phases |
| +$20c | driver state byte: 0 idle, 1 selecting, 2 phase dispatch, 3 ICCS issued, 4 data DMA running, 5 (unused here), 6 pad transfer, 7 message-in transfer |
| +$20d/+$20e/+$20f | last ESP status / sequence step / interrupt status |
| +$210 | current `sd` request pointer |
| +$214 / +$218 | current data address / remaining byte count |
| +$21b | low byte of `+$218` (count low) |
| +$21c | last message-in byte |

`sd` (SCSI request, built by the caller of `scsi_run_cmd`):

| offset | use |
|---|---|
| +0 | target ID (written to ESP +4) |
| +1 | LUN (low 3 bits, put into the IDENTIFY message) |
| +2 | direction: 0 = data out (write), non-zero = data in (read) |
| +4 | CDB (6, 10 or 12 bytes; the control byte must be 0) |
| +$10 | data address |
| +$14 | byte count |
| +$18 | residual count on completion |
| +$1c | SCSI status byte |
| +$1d | result state: 0 running, 1 selection timeout (no target), 2 complete, 3 error (set by `sub_0100e188`), 4 bad CDB, 5 bus reset seen |

mg fields: `mg+$186` softc, `mg+$19c` pointer to interrupt status register (`$02007000`),
`mg+$302` / `mg+$306` = SCSI interrupt handler pointer / argument (set to `scsi_intr` / softc by
`scsi_run_cmd`; the exception dispatcher is expected to call it on INT_SCSI), `mg+$4` bit 2 =
abort requested (checked in the wait loop).

### sub_0100d9b4 `scsi_init(mg)` (474 bytes, called from `sub_0100e188` (error recovery, mg = 0) and `$0100e210` (boot))
Register programming, in order:

1. `andi.b #$bf, $02114108` - floppy external control, clear bit 6 (`CTRL_82077`, floppy.c
   line 118: deselects the 82077 so the shared SCSI/floppy DMA and the ESP own the channel).
2. `softc = alloc(0x21e)`; if mg != 0 `mg+$186 = softc`. `softc+$20c = 0`, `softc+$2c = 6`,
   `softc+$1c = $02000010` (TDMA CSR).
3. `sub_0100e8cc(softc)` = DMA channel init: `softc+$2c &= $8fff`; **TDMA CSR = `$00100000`**
   (`DMA_RESET`); sets up the bounce buffer pointers.
4. `$02114020 = $22` (ENABLE_INT | RESET, 10 MHz clock select), delay 10 us,
   `$02114020 = $20` (ENABLE_INT only), delay 10 us.
5. ESP config 1 (`+8`) = `$57`: bit 6 SCSI-reset interrupt disabled, bit 4 parity enable, bus ID 7
   (bit 2 = slow-cable/"chip test" depending on datasheet numbering; `$57 = 0101 0111`).
6. Clock conversion factor (`+9`): the ROM assumes an ESP clock of **25 MHz on Turbo** (`$19`),
   20 MHz on non-Turbo (`$14`): CCF = 2 if clk <= 10, 3 if <= 15, 4 if <= 20, else 5 ->
   **5 on Turbo**, 4 on non-Turbo. (Previous uses ESP_CLOCK_FREQ 20.)
7. Select timeout (`+5`) = `(clk_MHz * 250000 + (CCF<<13) - 1) / (CCF<<13)` = 250 ms ->
   **`$99` (153)** for both 25/5 and 20/4.
8. Sync offset (`+7`) = 0 (asynchronous), sync period (`+6`) = 5, config 1 unchanged.
9. ESP command (`+3`) = `$03` **SCSI bus reset**, delay 2,000,000 us (2 s).
10. Read interrupt status (`+5`) twice into `softc+$20f` (clears the reset interrupt).
11. ESP config 1 (`+8`) = `$17` (as `$57` but SCSI-reset interrupt reporting re-enabled).
The ESP interrupt is left enabled in the DMA control register (`$20`) from step 4.

### sub_0100db8e `scsi_run_cmd(mg, unused, sd)` (182 bytes, called from `$0100e4f8`, `$0100e76a`)
`mg+$302 = scsi_intr`, `mg+$306 = softc`; `scsi_start(softc, sd)`. Then, while `sd+$1d == 0`:
delay 10,000 us; if the interrupt status register (`*mg+$19c`) has bit 12 (`INT_SCSI =
$00001000`) call `scsi_intr(softc)` directly (the ROM polls; it does not rely on the vectored
interrupt). Each iteration also calls the console poll `sub_0100a1a8` and clears `mg+$4` bit 2;
after 1000 iterations (10 s) prints `sc: Didn't complete` via `sub_0100e188` and returns 0.
Returns 1 only if `sd+$1d == 2` and `sd+$1c == 0` (GOOD status).

### sub_0100dc44 `scsi_start(softc, sd)` (266 bytes) - "scstart"
* CDB length from opcode group (`cdb[0] & $e0`): $00/$C0 -> 6, $20/$40/$E0 -> 10, $A0 -> 12,
  else invalid; the control byte (cdb[5]/[9]/[11]) must be 0. On violation `sd+$1d = 4`, return.
* `sd+$1d = 0`, `sd+$18 = sd+$14`, `sd+$1c = 0`. If `softc+$20c != 0` prints `sc: scstart: bad state`
  (and continues).
* `softc+$210 = sd`, `+$214 = sd+$10`, `+$218 = sd+$14`, state = 1.
* ESP: command `$01` (flush FIFO); delay 10 us; `+4` (select bus ID) = target; FIFO <-
  `$80 | (lun & 7)` (IDENTIFY, no disconnect); FIFO <- CDB bytes; command `$42`
  (**SELECT WITH ATN**). The interrupt (FC|BS) is handled by `scsi_intr` state 1.

### sub_0100dd4e `scsi_intr(softc)` (258 bytes) - "scintr"
1. If state == 4 (DMA transfer running): delay 20 us; if `sd+$2` (data in) then 3 times
   `{ $02114020 = $3C (ENABLE_INT|MODE_DMA|DMA_READ|FLUSH); 5 us; $02114020 = $38; 5 us }`, then
   20 us. Then `$02114020 = $20` (back to PIO, interrupt enabled).
2. `softc+$20d = status (+4)`, `+$20e = seqstep (+6)`, `+$20f = intstatus (+5)` (the read clears the ESP interrupt).
3. If intstatus bit 7 (SCSI reset detected): up to 10 times { delay 1 s; console poll; re-read
   intstatus } until bit 7 clears; if it never clears: config 1 = `$57` (mask reset interrupt),
   `sd+$1d = 5`. Return.
4. If status bit 6 (gross error) or intstatus bit 6 (illegal command) -> `sc: software error`;
   status bit 5 -> `sc: parity error` (both through `sub_0100e188`, which also re-inits the ESP).
5. Otherwise dispatch on state through `scsi_intr_state_tab` (`$01012a3c`):
   0 -> `scintr program error`; 1 -> `scsi_intr_selected`; 2 -> program error; 3 -> `scsi_intr_status`;
   4 -> `scsi_intr_dma_done`; 5 -> `scsi_intr_complete`; 6 -> `scsi_intr_state6`; 7 -> `scsi_intr_msgin`.
6. After the case, if state == 2 call `scsi_phase_dispatch(softc)`.

State cases:
* `scsi_intr_selected` (`$0100de50`): intstatus bit 5 (disconnect = selection timeout) ->
  `sd+$1d = 1`, state 0, current cleared. Else requires `seqstep & 7` in {2, 4} and intstatus ==
  `$18` (FC|BS) -> state 2; else `sc: selection failed`.
* `scsi_intr_state6` (`$0100de86`): state = 2.
* `scsi_intr_dma_done` (`$0100de9a`): `resid = ESP count (+1)<<8 | (+0)`; `softc+$214 += transferred`,
  `+$218 = resid`; state 2; `sub_0100ea5a(softc, resid)` (dma_cleanup: dma_stop = **TDMA CSR =
  `$00100000` (RESET)** after reading the CSR status and next pointer; copies bounce buffer data back
  for dev->mem transfers); if `softc+$2c & $4000` -> `sc: bus error`.
* `scsi_intr_status` (`$0100dee2`, state 3 = after ICCS): intstatus bit 5 -> `sc: target aborted`;
  needs intstatus bit 3 (FC) and `FIFO flags & $1f == 2` else `sc: fifo level`; then state 2,
  `sd+$1c = FIFO` (status byte), `softc+$21c = FIFO` (message byte), `sub_0100e11e(softc)` (message-in
  handler, next range: sends MSGACC `$12` / handles COMMAND COMPLETE -> state 5).
* `scsi_intr_msgin` (`$0100df1e`, state 7): intstatus bit 5 -> `sc: target aborted2`; FIFO level must
  be 1 else `sc: msgin fifo level`; `softc+$21c = FIFO`, `sub_0100e11e`.
* `scsi_intr_complete` (`$0100df5e`, state 5): state 0, current cleared, `sd+$18 = softc+$218`,
  `sd+$1d = 2`.

### sub_0100df9e `scsi_phase_dispatch(softc)` (70 bytes)
ESP command `$01` (flush FIFO), then jump on `status & 7` through `scsi_phase_tab` (`$01012a5c`):
0 DATA OUT -> `scsi_phase_data_out`; 1 DATA IN -> `sub_0100e05e` (next range); 2 COMMAND ->
`sc: SCSI command phase` (error: the CDB was already sent with SELATN); 3 STATUS -> `sub_0100e0e6`
(state 3, ESP command `$11` ICCS); 4, 5 -> command phase error; 6 MSG OUT -> `sub_0100e106`
`sc: SCSI msgout phase`; 7 MSG IN -> `sub_0100e0f4` (state 7, ESP command `$00` then `$10`
transfer information).

### sub_0100dfe4 `scsi_phase_data_out` (122 bytes, table `$01012a5c[0]`)
`sd+$2` must be 0 else `sc: SCSI bad i/o direction`. If the remaining count is 0: state 6,
ESP count = `$0100` (low 0, high 1 = 256), FIFO <- 0, command `$00` then **`$98`** (DMA | PAD:
pads the unexpected data phase with zero bytes). Otherwise: state 4;
`sub_0100e94a(softc, softc+$f4, addr, count, 0)` (dma_setup, builds the descriptor at `+$f4`
with bounce-buffer handling for unaligned addresses); `sub_0100eacc(softc, softc+$f4, 0)`
(dma_start: **TDMA CSR = dir | `$00100000` (RESET) | `$00800000` (Turbo: BUFRESET; non-Turbo
`$00200000` INITBUF)**, then `+$4000` = next, `+$4004` = limit, and if a second descriptor is
chained `+$4008`/`+$400c` = start/stop and **CSR = dir | `$00030000` (SETENABLE|SETSUPDATE)**,
else **CSR = dir | `$00010000` (SETENABLE)**); ESP count low = `softc+$21b`, high = count >> 8;
ESP command `$00` then **`$90`** (DMA | TRANSFER INFORMATION); `$02114020 = $30`
(ENABLE_INT | MODE_DMA, direction mem->scsi). The DATA IN twin (`sub_0100e05e`, next range) is
identical with `dir = $40000` (DMA_DEV2M) and `$02114020 = $38` (…| DMA_READ).

Summary of the SCSI DMA control register values the ROM uses: `$22` (reset ESP), `$20` (PIO,
interrupt on), `$30` (DMA out), `$38` (DMA in), `$3C` (DMA in + flush). TDMA CSR values:
`$00100000` reset/stop, `dir|$00900000` (Turbo) before loading pointers, `dir|$00010000` start,
`dir|$00030000` start with single-update chaining, where dir = `$00040000` for device->memory.
The ROM's first touch of the ESP is in the exception dispatcher (`$01001a06`: `$02114020 = $02`,
then ESP command `$03` bus reset) before `scsi_init` ever runs.

## Machine-type applicability

* Everything in the ADB driver is Turbo-only in practice (`adb_init` is skipped on `$139`
  machines, `adb_kbd_raise_nmi` and `adb_set_config` test it explicitly). The ADB window
  exists on all TMC boards; the FPGA core must implement `$02208000..$02208088` with the
  polled semantics above (INTSTATUS write-back ack, ACCESS/DATAPEND, COUNT in bits) if an ADB
  keyboard is to be presented. If no device answers TALK reg 3 at addresses 1..7 (`COUNT` stays 0
  / `STATUS` DATAPEND clear after ACCESS) the ROM falls back to the KMS keyboard path.
* `vid2_enable` / `vid2_set_brightness` apply to whichever machine selects video driver 2
  (`mg+$34d = 2`); the TMC video-enable write inside is Turbo-only.
* The SCSI driver is common to all 68040 machines; only the ESP clock assumption (25 vs 20 MHz)
  and the TDMA `BUFRESET` vs `INITBUF` bit differ.
