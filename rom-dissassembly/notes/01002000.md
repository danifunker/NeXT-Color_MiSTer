# ROM range $01002000..$01003FFF (Rev 3.3 v74)

Content: monitor command handlers (`p`, `m`, `s`, `e`, `S`, `R`, `?`, `c`, `d`, `r`), the
NVRAM-parameter and system-register edit machinery, bus-error-protected probe reads, the
password check, the DRAM configuration (SIMM sizing) tests, the full DRAM tests, the VRAM
test, the pre-stack VRAM/DRAM probes used by reset, and the parity probes.

Conventions used below: `mg` = monitor globals pointer (from `sub_01000686` = `4(vbr)`),
`mg_nvram` = `mg+$16`, `mg_simm[i]` = byte `mg+i` (i = 0..3, one SIMM code per bank),
`mg_region[i]` = `{base,size}` at `mg+$c8+8*i`. `printf` = `sub_01007772`, `aprintf` =
`sub_0100785c` (same formatter with a second argument of 2, apparently the "alert"/console
variant used for POST messages), `bzero` = `sub_01007ffc(addr,len)`, `gets` =
`sub_01007b5c(buf,max,echo)`, `parse_num` = `sub_01007cd8(str,&val,radix)` (returns pointer
past the number or 0; radix 0 = default `mg+$192`), `strcmp` = `sub_010080d8`, `strcpy` =
`sub_010080f8`, `strlen` = `sub_01008130`, `skipws` = `sub_01007ca8`.

## Machine-class facts used by every routine here (verified)

* `mg+$194` is set to `$139` by `sub_01000c9c` for machine types 0..3 (68030 cube, station
  mono, cube 040, station colour) and left 0 for types 4..0xB (all Turbo). Every routine in this
  range decides Turbo vs non-Turbo with `cmpi.l #$139,$194(mg)`. Call it `mg_board_class`
  (0x139 = non-Turbo, 0 = Turbo).
* Bank stride, computed identically in 8 places (`$194==$139` ? (`$3a8==3` ? `$2000000` :
  `$4000000`) : `$8000000`, then `asr #2`):

  | class | stride | bank bases |
  |---|---|---|
  | non-Turbo mono/cube (types 0,1,2) | 16 MB | `$04000000, $05000000, $06000000, $07000000` |
  | non-Turbo colour (type 3) | 8 MB | `$04000000, $04800000, $05000000, $05800000` |
  | **Turbo (types 4..0xB, our target)** | **32 MB** | `$04000000, $06000000, $08000000, $0A000000` |

* SIMM code tables (4-bit code = bits 1:0 size, bit 2 page mode, bit 3 parity), bytes stored
  in `mg_simm[i]` and later in NVRAM bytes 10/11:
  * non-Turbo sizes `dat_01014a64[16]`: code&3 → 0, 16 MB, 4 MB, 1 MB (bank size); names
    `dat_010149e4[16]`: "no", "16MB of nibble mode", "4MB of nibble mode", "1MB of nibble mode",
    "illegal", "16MB of page mode", "4MB of page mode", "1MB of page mode (illegal)", then the
    same with "parity" for codes 8..15.
  * **Turbo sizes `dat_01014aa4[16]`**: code&3 → 0, 32 MB, 8 MB, 2 MB (bank size = SIMM pair);
    names `dat_01014a24[16]`: "no", "32MB of page mode", "8MB of page mode", "2MB of page mode",
    "illegal", (repeat), "32MB of parity page mode", "8MB of parity page mode", "2MB of parity
    page mode". These match `SIMM_32MB_T=1, SIMM_8MB_T=2, SIMM_2MB_T=3, SIMM_PARITY=8` in
    rtcnvram.c lines 913-925. Both tables are mislabelled `sub_` by the generator (they are data).
* `mg+$3ba` = 0 for types 0,1,2 (four SIMM sockets per bank) and 1 for all others (SIMM pairs);
  `mg+$3b6` picks the failure icon (1 = colour-ish variants). Set in the type dispatch at
  `$01000d64..$01000dc8`.
* `mg+$170` (word) flag bits: bit 3 is set (and bit 0 cleared) whenever a warning/alert has
  been printed (config test result 2, parity error handler `$01001cd8`, `mon_print_warning`);
  `vid_vram_test(0)` clears bit 3 at reset. Bit 0 meaning unknown.
* `mg+$1a4` = bus-error recovery continuation (long, 0 = none). `mg+$1a8` = last examine size
  letter ('l'/'w'/'b', initialised to 'l' by `sub_01000c9c`), `mg+$1aa[8]` longs = last examine
  address list, `mg+$1ca` = its count. `mg+$192` = default input radix (init 16).
  `mg+$320` = allocation/stack-page pointer, `mg+$31c` = -1 at init (unknown).

## Reset-path facts corrected by this range

The brief says the initial stack is in VRAM. That is only true for **mono** machines. From
`$0100042e`: colour types 3, 5, 7, 9, 0xB branch to `loc_01000508`, which sets `a7 = sub_01000514`
(a continuation, there is no stack yet) and runs `mem_dram_probe` (`loc_01003dfc`) with
`a0 = $04000000`, `d3 = stride` (8 MB for type 3, 32 MB for Turbo), `a6 = end` (`$06000000` for
type 3, `$0C000000` for Turbo). The first bank whose first 8 KB passes becomes the initial
stack: `sub_01000514` does `a0 += $800; a7 = a0`, the mg struct is at `bank+$800`, the vector
table at `bank+$C00`. **On Turbo Color the initial stack, mg and vectors are in DRAM bank 0
(`$04000800..$04001000`), not in VRAM.** Then `vid_vram_test(0)` (`sub_01003a9c`) is called at
`$0100054e` to test the whole 2 MB of VRAM before continuing to `loc_01000556`. Mono types take
`loc_010004c2` -> `vid_vram_probe` (`loc_01003ca4`) and put the stack at VRAM+$3F800 as the
brief says; they never run `vid_vram_test` at reset.

Every later DRAM test therefore checks whether a bank base equals `(a6-4) & ~$1FFF` (the 8 KB
page holding the current stack frame) and if so skips the first `$2000` bytes of that bank.

## Monitor commands (all end with `bra loc_01001df0`, the command-loop return)

The dispatch table at `$01011c40` is indexed by `char - '?'`; in these handlers `a3` = rest of
the command line, `a4` = mg, `a5` = `mg_nvram`, `d3` = the monitor's current function code,
`a6` frame holds the saved register frame at `8(a6)`. Help text (`$01014cd8`, printed by
`mon_print_help`) lists: p, a [n], m, d [n], r [regname], s [systemreg], e [lwb] [alist]
[format], ec, ej, eo, ef, c, b, S [fcode], R [radix].

### `mon_param_edit_table` sub_01002630 (line, table, base, prefix) -> d0 = 1 if something changed

Parameter tables are arrays of 20-byte entries `{name*, offset, handler*, arg, 0}` terminated
by a 0 name. For each entry (skipped if `line` is non-empty and `strcmp(line,name)!=0`):
print `"%s%s: "` (prefix, name) if name non-empty; if `handler==0` print `"%08x? "` of the long
at `base+offset`, else call `handler(0, base, entry)`; `gets(buf,$80,1)`; empty input -> next
entry. No handler: `'.'` -> stop; `mon_password_check(0)` fails -> stop; `parse_num(buf,&v,16)`
fails -> stop; else store long at `base+offset`, changed=1. With handler:
`r = handler(1, base, entry, buf)`; r == -1 or 1 -> stop, else changed=1.

Handler calling convention: `(mode, base, entry, line)`; mode 0 = display, 1 = modify; return
0 ok, -1 error/abort, 1 = stop iterating.

* `mon_param_sysreg` sub_0100274e: `a2 = base + entry.offset`. If `entry.offset == $0200C000`
  and `SCR1 byte 2 >> 4 == 4` (raw type nibble reads 4, i.e. Turbo) then `a2 = base + $02200000`
  (TMC SCR1 copy). Mode 0: `printf("%b? ", *a2, entry.arg)`. Mode 1: `parse_num(line,&v,16)` and
  `mon_password_check(0)`, then `*a2 = v` (long write to the register); -1 on failure.
  For `sr` in the `r` table the "register" is the frame word at +$82 (read as a long).
* `mon_param_bootcmd` sub_010027e2: display `"%s? "` of `nvram+$12`. Modify: password;
  `'.'` clears the string and returns 1; `strlen(line) >= entry.arg(12)` -> `"must be < %d chars
  long\n"`, -1; else `strcpy(nvram+$12, line)`.
* `mon_param_pot_bit` sub_0100287c: display `"yes"/"no"` (`" %s? "`) of `nvram[14] & mask`.
  Modify: `'.'` -> -1; password; `y/Y` sets, `n/N` clears the byte mask (`entry.arg` low byte).
* `mon_param_parity` sub_0100291a: same with `nvram[17] bit 2` (USE_PARITY_MEM).
* `mon_param_reset_bit` sub_010029aa: same with the long at `nvram+0` and the 32-bit mask.
  Password check is `mon_password_check(1)` (forced). Clearing the mask `$04000000` (allow
  eject) requires `sub_0101034c()` (optical drive 0 has a disk) != 0, else prints "There must be
  a disk inserted in drive #0 before you can set this option\n" and returns -1.

### `mon_cmd_p` sub_0100213a
`mon_param_edit_table(args, $010148c0, mg_nvram, "")`; if changed, `sub_0100866c(mg_nvram)`
(NVRAM write-back). `mon_cmd_s` sub_01002168 picks the table by `mg+$194` and calls with base 0.
`mon_cmd_d` / `mon_cmd_r` (and `a` at $01001ffe) push the table, `8(a6)` (saved register frame)
and a prefix ("d", "", "a") and share `mon_cmd_regs_common` loc_0100218a.

### `mon_cmd_m` sub_0100203a ("print memory configuration")
`mg+$3ba == 0` (types 0,1,2): for banks 0..3 (type 1 stops after bank 1):
`"Memory sockets %d-%d have %s SIMMs installed (0x%x-0x%x)\n"` with sockets `4i..4i+3`, name
`dat_010149e4[mg_simm[i]]`, `mg_region[i].base/size`.
`mg+$3ba == 1`: type 3: `"Memory sockets %d and %d have %s SIMMs installed (0x%x-0x%x)"` with
sockets `2i, 2i+1`, names from `dat_01014a24`; **Turbo**: `"Memory sockets %d and %d (%s) have
%s SIMMs installed (0x%x-0x%x)"` with sockets `(i&~1), (i&~1)+1` and `"front"` for even banks
/ `"back"` for odd banks. So on Turbo, banks 0/1 are the front/back SIMM pair of sockets 0-1 and
banks 2/3 the front/back pair of sockets 2-3.

### `mon_cmd_e` sub_0100219a
First char of args: `'c'` -> `printf("Old error code: %x\nLast error code: %x\n", nvram[15],
nvram[16])`. `'f'`, `'j'`, `'o'`: scan the args for a '0' or '1' digit (unit, default 0);
`'f'` -> `sub_01010700(unit)` (floppy eject), `'j'`/`'o'` -> `sub_0101027e(unit, 0)` (optical
eject). Anything else -> `mon_examine_memory(args, d3)`.

### `mon_examine_memory` sub_01002a68 (args, fcode)
If args empty, uses `mg+$1a8` (last size letter). `'l'` size 4, read `sub_0100070e`, write
`sub_0100075e`, fmt "%08x"; `'w'` size 2, `sub_01000728`/`sub_0100077c`, "%04x"; `'b'` size 1,
`sub_01000742`/`sub_0100079a`, "%02x"; the letter is stored in `mg+$1a8`. The read primitives
(`$0100070e..$010007b6`, outside this range) do `movec sfc/dfc` from the third argument and
`moves` from/to the address, so the examine command reads any function-code space (the `S`
command sets `d3`; FC names table `$010149c4`: 0 "0", 1 "UD", 2 "UP", 3 "3", 4 "4", 5 "SD",
6 "SP", 7 "cpu"). Up to 8 addresses are parsed (radix 0 = default) into `mg+$1aa[]`, each
masked with `-size`; count in `mg+$1ca`; no address and no previous list -> `mon_usage_error`.
Remaining text is used as the printf format (user override). Loop: `printf("%x: ", addr)`,
`v = read(addr, 1, fcode)`, `printf(fmt, v)`, `printf("? ")`, `gets`; non-empty input ->
`parse_num` (failure exits) then `write(addr, 1, fcode, v)`. With one address it advances by
`size`; with several it cycles `d2 = (d2+1) % count`.

### Others
* `mon_cmd_fcode` sub_0100223a: `parse_num(args,&v,10)`; `d3 = v & 7`; prints
  `"Function code %d (%s)\n"`.
* `mon_cmd_radix` sub_01002278: `parse_num(args,&v,10)` -> `mg+$192 = low byte`; prints
  `"default input radix %d\n"`.
* `mon_cmd_help`/`mon_print_help`: `printf("%s", help)`. `mon_cmd_huh` prints "Huh?\n".
* `mon_cmd_continue` loc_010022cc: `movem.l -$38(a6),d2-d6/a2-a5; unlk a6; rts` (returns from
  the monitor to the exception dispatcher which then `rte`s to the saved pc).
* `mon_password_check` sub_010024f6 (force): field `bfextu nvram+2{2:4}` (ni_reset bits 13:10,
  "hardware password") != 6 -> return 1 (no password). `mg+4` (mg_flags) bit 7 set -> 1
  (already authenticated). `!force && nvram[3] bit 0` (any-cmd allowed) -> 1. Else prints
  "Password: ", `gets(buf,16,0)` (no echo), prints "\n", compares 6 bytes: `buf[i] ^ 'N'` must
  equal `nvram[4+i]` (bytes 4..9 hold the password XOR $4E). Mismatch -> "Sorry\n", buffer
  cleared, return 0. Match -> `mg_flags |= $80`, return 1.
* `mon_probe_read_byte` sub_0100237a (src, dst), `mon_probe_write_byte` sub_010023b8 (dst,
  byte), `mon_probe_read_long` sub_010023f6 (mg, addr): store a continuation in `mg+$1a4`, do the
  access, clear `mg+$1a4`, return 1; the exception dispatcher resumes at the continuation
  (`sub_010023aa`, `loc_010023e8`, `loc_0100241c`) on bus error, which returns 0. Used by device
  probing (`$01008d8a`, `$0100ad74`...).
* `mon_print_warning` sub_01002426 (str): if `mg+$170` bit 3 clear: clear bit 0, set bit 3;
  then `printf(str)`.
* `mon_system_test_failed` sub_01002462 (halt): if halt: `sub_01004440(0x154,0x134,image
  $01015f74)` and `sub_01004440(0x280,0x161, mg+$3b6 ? $01015264 : $01015040)` (draw icons);
  always `sub_010077a4(0x226,0x17c,1,"System\ntest\nfailed")` (draw text); if halt, loop
  forever calling `sub_0100a1a8` (power-key handler, "really power down?").
* `mon_led_blink` sub_010025d4 (n): n times { `SCR2 |= 1` (LED on, `$0200D003` bit 0),
  1,000,000-iteration delay, `SCR2 &= ~1`, delay }, then one more delay.
* `mon_usage_error` sub_010025c0: prints the usage error string.

## Memory-region setup

### `mem_build_regions` sub_010022d6 (mg)  — called from `$010014f0` after NVRAM read
Size table `a2 = dat_01014a64` (non-Turbo) or `dat_01014aa4` (Turbo) chosen by `mg+$3ba`
(0 / 1). For i = 0..3: if `mg_simm[i] != 0`: `mg_region[i].base = $04000000 + i*stride`,
`.size = base + table[code]` (note: **size field holds the end address, base+size, not the
length**); else both 0. This confirms `mg+$c8` = `mg_region[4]` of `{base, end}`.

## Non-Turbo DRAM configuration test (types 1,2,3; not used on Turbo)

### `mem_config_test_nt` sub_01002e4c (mg) -> 0 ok, 1 failed, 2 parity warning
Called from `$0100107a` (68040 non-Turbo path of `sub_01000ec6`). Per bank i (bank base
`$04000000 + (i<<24)` – always 16 MB stride here, even for type 3), using SCR2 `$0200D000`
memory-configuration bits `bit(16+i)` ("mem1M/4M" nibble at SCR2 bits 19:16, one per bank)
and `bit(20+i)` ("mem256K/4M", bits 23:20):
1. `SCR2 |= $110000<<i` (both bits). `mem_bank_present_nt(base)` == 0 -> `mg_simm[i]=0`, next.
2. `mem_burst_test_nt(base)` ok (page-mode SIMMs): `mg_simm[i] = mem_bank_size_nt(base)` = 5 /
   6 / 7 (16 MB / 4 MB / 1 MB page mode) or 0 -> error report.
3. Else clear both bits, `mem_write_read_long(base)` ok -> code 1 (16 MB nibble); else set
   `bit16+i` only -> code 2 (4 MB nibble); else `bit20+i` only -> code 3 (1 MB nibble); else set
   both, code 0, `mem_report_error_nt(base)`, result 1.
Second pass: every present bank must still pass `mem_burst_test_nt`, else `"Bank %d has mixed
mode SIMM's\n"`, code 0, result 1.
Third pass (parity): for each present bank, vector 2 (bus error) of the live table is replaced
by `mem_berr_parity_nt` (`BMAP+8 = 0; rte`), `cpusha`, `BMAP $020C0008 byte |= $80` (parity
check enable), 4 longs of 0 then 4 longs of `$01010101` are written/read with `cpusha`s, vector
restored. If `BMAP+8` bit 31 is now 0 (the handler cleared it: parity error = non-parity SIMM)
-> flag "non-parity present"; else `bzero(base, size)` (initialise parity), `mg_simm[i] |= 8`,
flag "parity present". If both flags and `nvram[17] bit 2`: `"All of the SIMMs must be parity
SIMMs if you want parity to work.\n"`, result 2. If no non-parity bank and `nvram[17] bit 2`:
`mg+$3ae |= $80000000` (parity enabled, BMAP bit stays set). Otherwise `BMAP+8 byte &= $7F`,
then 5 bytes from the timing table `dat_01014af8` (index = type*160 + (SCR1 mem-speed bits 5:4
+ 4*cpu-speed bits 2:0)*5) are written to `$02106010..$02106014`, and for types 1/2 with
`mg+$3a9 == 1` (board rev): `BMAP+$30 |= $40000000`, `BMAP+$34 &= ~$40000000`. Non-Turbo only;
ignore for the FPGA core.

Helpers: `mem_bank_present_nt` sub_01002d92 (8 longs cleared, each read twice must be 0),
`mem_bank_size_nt` sub_01002dbe (writes `$12345678` at base, `$89ABCDEF` at +4 MB,
`$ABCDEF01` at +1 MB, `cpusha`; reads base: `$89ABCDEF` -> 6, `$12345678` -> 5, `$ABCDEF01` -> 7,
else 0), `mem_write_read_long` sub_01002e24, `mem_burst_test_nt` sub_01003d4a (writes
`$01234567 $89ABCDEF $092B4D6F $81A3C5E7`, `cpusha`, `cacr = $80008000` (both caches on),
`tst.b 4(a0)` forces a line fill, compares the 4 longs, returns 1 if equal, then `cpusha`,
`cacr = $8000` — note it leaves the data cache disabled).

### `mem_test_all_nt` sub_01003224 (mg) -> 1 if any bank failed
`sub_010040c4(0)` (SCR2 |= 1, LED on), `sub_010040ac(0)` (cinva, cacr = 0, old cacr saved).
For each present bank: `mem_pattern_test_nt(base, dat_01014a64[code & ~$C])`; failure address
-> caches off again, `mem_report_error_nt(addr)`. Finally cacr restored, LED off.

### `mem_report_error_nt` sub_01002cd2 / `mem_print_bad_sockets_nt` sub_01002c54
`aprintf("\nMemory error at location: %x\n", addr)`, `"Value at time of failure: %x\n"`; writes
`$55555555` at addr and `$AAAAAAAA` at addr+4, reads addr: mismatch -> sockets with pattern
$55 and type -1; else `$AAAAAAAA`/`$55555555`, mismatch -> pattern $AA, type -2; else
`"Coupling dependent memory fault!\n"`, `"One or more SIMM at memory bank %d is bad\n"` (bank
= (addr>>24 & $F) - 4), `"Note: bank 0 is the first bank\n"`.
`mem_print_bad_sockets_nt(addr, pattern, &value, type)`: `"\nDRAM error type %d\n"` (-1/-2),
`"Check socket (0 is the first socket): "`, then for each byte lane k=0..3 whose byte differs
from the pattern prints `"%d "` = `bank*4 + 3 - k`, then "\n\n".

## Turbo DRAM configuration test (types 4..0xB, and type 3) — **Turbo Color path**

### `mem_config_test_t` sub_0100361a (mg) -> 0 ok, 1 failed, 2 parity warning
Called from `$01001256` (Turbo/colour path of `sub_01000ec6`), result handled exactly like the
non-Turbo one (1 -> "Main Memory Configuration Test Failed" + `mon_system_test_failed`).

Pass 1, per bank i (base `$04000000 + i*$2000000`):
* `mem_bank_absent_t(base)` (sub_0100353e): writes `$55555555` at +0 and `$AAAAAAAA` at +4, +8,
  +$C, `cpusha`, reads back; any mismatch -> returns 1 -> `mg_simm[i] = 0`.
* `d4 = mem_bank_size_t(base)`, `d3 = mem_bank_size_t(base+4)` — the two longwords of an
  aligned 8-byte pair sit in the two SIMMs of the pair (interleave on address bit 2), so both
  members are sized. `mem_bank_size_t` (sub_01003598, addr): writes `$12345678` at addr,
  `$89ABCDEF` at addr+$800000 (skipped for type 3), `$ABCDEF01` at addr+$200000, `cpusha`,
  reads addr: `$89ABCDEF` (aliases at 8 MB) -> 2 (8 MB pair, 4 MB SIMMs); `$12345678` (no alias)
  -> 1 (32 MB pair, 16 MB SIMMs; 2 on type 3 = SIMM_8MB_C); `$ABCDEF01` (aliases at 2 MB) -> 3
  (2 MB pair, 1 MB SIMMs); anything else 0 -> `mem_report_error_t(addr)`, result 1.
* `d4 != d3` -> `"Bank %d has mixed size SIMMs.\n"`, `mg_simm[i] = 0`, result 1; else
  `mg_simm[i] = d4`.
  Address patterns for the FPGA: DRAM writes at `bank+0`, `bank+4`, `bank+$200000`,
  `bank+$200004`, `bank+$800000`, `bank+$800004`, reads at `bank+0/+4`. A 32 MB bank must not
  alias at 8 MB or 2 MB; an 8 MB bank must alias at 8 MB (address bit 23 ignored).

Pass 2 (parity probe), per present bank:
* type 3 (non-Turbo colour): save vbr, `vbr = mem_vectors_nt` (`$01003fc2`, vector 2 =
  `mem_berr_parity_vec_nt`), `cpusha`, `mem_parity_probe_nt(base)`: `BMAP+8 = $80000000`, then
  `mem_parity_probe_body`, then `d0 = BMAP+8 & $80000000`, `BMAP+8 = 0`; vbr restored.
* **Turbo**: `cpusha`, save vbr, `vbr = mem_vectors_t` (`$01003ff2`, 32 entries, vector 31 =
  level-7 autovector = NMI = `mem_nmi_parity_vec_t`: `$02200004 = 0`, `TMC ctrl $02200010 &=
  ~$400`, `rte`), `mem_parity_probe_t(base)` (unlabeled code at `$01003ee8`):
  `TMC ctrl |= $400` (parity checking enable, bit 10), then `mem_parity_probe_body`: 4 longs of
  0 at base, `cpusha #1`, read +0/+4; 4 longs of `$01010101`, `cpusha`, read; 32 bytes of 0
  then bytes at +3,+7,+$A,+$E,+$11,+$15,+$18,+$1C set to 1, `cpusha`, read all 32 bytes;
  then `mem_parity_probe_t_done`: `d0 = TMC ctrl & $400`, `TMC ctrl &= ~$400`, rts. So the
  result is "parity SIMMs present" iff no parity NMI fired during the reads. vbr restored.
  (`sub_010040bc` = `cpusha #1` after the vbr store.) The parity-error NMI status
  register `$02200004` (with address `$02200008` and data `$0220000C`, see the message at
  `$01001cf8`) is cleared by the handler.
* Parity present: flag `d5`; `bzero(base, size)` — or `bzero(base+$2000, size-$2000)` if the
  stack page is at `base` — to initialise parity bits, `cpusha`, `mg_simm[i] |= 8`. Absent: flag
  `d4`.

After the loop:
* `d5 && d4 && nvram[17] bit 2` -> `"All of the SIMMs must be parity SIMMs if you want parity
  to work.\n"`, result 2.
* `d4 == 0` (every present bank has parity) `&& nvram[17] bit 2` -> `mg+$3ae |= $80000000`;
  type 3: `BMAP+8 byte |= $80`; **Turbo**: `sub_01004072($04000000, $04002000)`: for every long
  of the first 8 KB page of bank 0: read, `TMC ctrl |= $400`, write back, `TMC ctrl &= ~$400`;
  finally `TMC ctrl |= $400` (parity checking left enabled); then each present bank is
  `bzero`ed again (skipping the stack page) with parity on; then `$02200004 = 0` written twice
  (clear parity NMI status).
* otherwise, type 3 only: byte `$0B` written to `$02118190`.
* Finally `d1 = 1`; any present bank without bit 3 -> `d1 = 0`; if not type 3 and `d1 == 0`:
  **`TMC ctrl $02200010 &= ~8`** (bit 3 cleared: "no parity memory" bit in byte 2 of the
  control register; Previous's `tmc_ctrl_write2` masks `0x04` of that byte = ctrl bit 10, so the
  emulator treats bit 10 as the parity-memory bit and this bit 3 write is unmodelled). Note
  bit 3 is never set by the ROM in this range; reset value `$0D17038F` has it set.

TMC control register writes in this range, in order for a Turbo machine with parity SIMMs and
parity enabled in NVRAM: `|= $400` / `&= ~$400` per bank probe (plus NMI handler clears);
`|= $400`/`&= ~$400` per long of bank 0 page 0 then `|= $400`; `$02200004 = 0` x2. Without
parity SIMMs: `|= $400`, `&= ~$400` per bank, then `&= ~8`.

### `mem_test_all_t` sub_010039bc (mg) -> 1 if any bank failed
`sub_010040ac(0)` (caches off). For each present bank: `base`, `size = dat_01014aa4[code &
~$C]`; if the stack page is at `base`, test `(base+$2000, size-$2000)`; `mem_pattern_test_t`;
failure -> caches off, `mem_report_error_t(addr)`. cacr restored. No LED handling here (the
non-Turbo version toggles the LED).

### `mem_pattern_test_t` sub_01003456 / `mem_pattern_test_nt` sub_0100313c (base, size)
`sub_010040ac($80008000)` (caches on, cinva). Three passes of: fill `[base, end)` with the
repeating triple `(d3, d2, d4)`, `cpusha`, verify; then "rotate" each register with
`x = (x << 1) & (x >>> 31)` (opcode `c681` = `and.l`, not `or.l`) — starting from `d3 =
$DB6DB6DB, d2 = d4 = 0`, so pass 0 writes `DB6DB6DB 00000000 00000000 ...` and passes 1 and 2
write all zeros (probably a ROM bug for an intended rotate). Then `sub_010040ac($8000)` (data
cache off) and a byte-lane test: bytes 1..4 (`_nt`) or 1..8 (`_t`, both SIMMs of the pair)
written at `base` and read back. Returns the first failing address (verify) / `base` (byte
test) or 0.

### `mem_report_error_t` sub_0100336a / `mem_print_bad_socket_t` sub_010032e0
Same messages as the non-Turbo version; `mem_print_bad_socket_t(addr, type)`: bank =
`(addr - $04000000) / stride`, socket = `bank*2 + (addr bit 2 ? 1 : 0)`, prints `"\nDRAM error
type %d\n"` (-1 first pattern, -2 second) and `"Check socket (0 is the first socket): %d\n\n"`.
Coupling fault case prints `"One or both SIMMs in memory bank %d are bad\n"`.

## VRAM

### `vid_vram_test` sub_01003a9c (quiet) -> failing address or 0
Called at reset (`$0100054e`, colour machines only, quiet = 0) after the DRAM stack exists.
quiet == 0: `sub_01000c9c(mg_sid, mg)` (device-pointer init), `mg+$320 = stackpage + $1000`,
`bzero(that, $400)`, `mg+$31c = -1`, `mg+$170 &= ~8`. VRAM base = `$2C000000` if
`mg+$194 == $139` (type 3) else **`$0C000000` (Turbo)**. All comparisons are masked with
`$FFF0FFF0`: **the low nibble of every 16-bit VRAM word is don't-care** (12-bit pixels).
1. fill 2 MB (`$200000` bytes, longs) with `$55505550`, verify;
2. fill `$AAA0AAA0`, verify;
3. address pattern: long i gets `($00100020 + i*$00200020) & $FFF0FFF0`, verify.
Failure: `mon_led_blink(3)` four times, `bad = read ^ expected`, nibble index d1 = first
non-zero nibble from the MSB (0..7), `|= 8` if address bit 2 set, `IC = dat_01015030[d1]`
(16 bytes "DHL\0CGK\0BFJ\0AEI\0"), then `printf` (quiet) or `aprintf` of `"VRAM failure at
0x%x:  read 0x%08x, expected 0x%08x, bad bits %08x, IC U%d\n"` (the IC letter is printed with
%d, i.e. as its ASCII code — as coded). Returns the address.

### `vid_vram_probe` loc_01003ca4 (pre-stack, mono machines; a0 = VRAM base, a6 = continuation)
`SCR2 |= 1` (LED on), `d2 = cacr`, `cpusha`, `cacr = $8000`, tests `[a0, a0+$40000)` (256 KB,
the region that will hold the stack/mg) with `$AAAAAAAA`, `$55555555` (`vid_vram_probe_fill`
loc_01003c84 with continuations `sub_01003ce2`, `sub_01003cfc`) and incrementing longs. Failure
-> `loc_010040ec` with `a0 = 3` (LED blink code 3, halt). Success: cacr restored, `SCR2 &= ~1`,
`jmp (a6)`.

### `mem_dram_probe` loc_01003dfc (pre-stack, colour machines; a0 = `$04000000`, d3 = stride, a6 = end, a7 = continuation)
Per bank: writes `$55555555` to +0,+4 and `$AAAAAAAA` to +8,+$C and compares (note +8 is
compared twice, +$C never — ROM bug); then `[a0, a0+$2000)` with `$DB6DB6DB`, its complement,
and incrementing longs (`mem_dram_probe_fill` loc_01003dcc, continuations `sub_01003e5c`,
`sub_01003e76`). Success -> `jmp (a7)` with a0 = bank base. Failure -> `a0 += d3`; when
`a0 == a6` -> `loc_010040ec` with `a0 = 5` (LED code 5 = no usable DRAM).

## Generator issues found (addresses)

* `$01003546..$01003597`: real code (body of `mem_bank_absent_t`) decoded as strings
  `str_01003548`/`str_01003572`.
* `$01003ee4..$01003f03`: real code decoded as `str_01003ee4`: `$01003ee4 movea.l (a7)+,a2;
  rts` (tail of `sub_01003ece`) and a routine entry at **`$01003ee8`** (`mem_parity_probe_t`,
  called by `bsr.l $1003ee8` at `$01003806`) that is not labelled.
* `sub_01003fc2` and `dat_01003ff2` are data: 12-entry and 32-entry exception vector tables
  (all `$010005ae` except entry 2 = `$01003f94` and entry 31 = `$01003fa2`). They are loaded
  into vbr by `sub_01000696` during the parity probes.
* `sub_01014a64`, `sub_01014a24`, `sub_010148c0`, `sub_010147f8`, `sub_01014730`,
  `sub_0101467c`, `sub_010145c8`, `sub_010149c4` are tables (their first long is a pointer),
  not code; `sub_01015040`, `sub_01015264`, `sub_01015f74` are bitmaps.
* `sub_01003e5c`/`sub_01003e76`/`sub_01003ce2`/`sub_01003cfc` are continuation targets loaded
  with `lea`, not real subroutines (they end with `jmp (aN)`).

## Uncertain

* Meaning of TMC control bit 3 (cleared when non-parity SIMMs are present) and of `$02200004`
  (treated as parity-NMI status because the handler clears it and the exception dispatcher
  prints it as "status").
* `mg+$170` bit 0, `mg+$31c`, `mg+$3a9` (board revision nibble from SCR1 bits 11:8?).
* The `$02106010` 5-byte timing write and the `$02118190 = $0B` write are non-Turbo only and
  were not investigated further.
* `sub_0100785c` as "alert printf" is inferred from its use for POST failure text only.
